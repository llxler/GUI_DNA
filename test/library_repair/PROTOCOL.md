# 冻结接口下的库实现修复（2026-11-13）

本阶段是看到第18–20节结果后设计的**事后诊断**，不替代原实验，不称未见需求迁移。比较“再给一次需求自查机会”与“同样一次机会加开发行为反馈”，检验已有实现对失败的贡献。用户授权本次新增API最多$10，工作总时限3小时；本阶段独立账本cap $9、stop $8.6，剩余$1不自动使用。原第三轮继续暂停。

## 输入与干预

- 固定calculator/table/bom的原六套模型库。由原建库者GPT-5 medium或Sonnet 4.5修复；原接口、说明、例子和schema不变，只能替换完整files与compiler。要求保留原有选项语义，格式验证无法保证语义完全没变，解释时披露。
- 开发任务预定为2/6/10/14/18，评估里程碑为4/8/12/16/20；按任务编号划分，与具体得分无关。五个开发任务原GPT-OSS最终合法方案固定为行为检查配置。错误配置也可能使开发测试无法通过，修复不能把所有失败都归为库错误。
- 两种条件都见全部20项公开需求、原包和上述五个配置。review只收到需求自查指令；feedback另收到这五个官方文件的已有实际观察。只提取各公开文件的标题、状态、清除源码框/堆栈后的错误；不加入其他文件或原隐藏成绩。没有参考源码。
- 每库每条件只采一个有效模型响应，输出上限26000 tokens（含推理）。没有根据新测试得分选择版本，也不给第二次行为修复。12次有效响应全部完成、库冻结后再开始新评分。长度截断/格式无效作为完整失败保留，该条件部署原库作明确的回退，不重抽；传输不完整不算有效模型输出，只补同一个请求，原记录与未知预留保留。
- 有效修复必须只给files/compiler，两个原文档例子通过原模式、确定性编译。其余字段逐字保持；不根据开发通过率挑选或退回旧库。若合法修复使原方案编译失败，记为实现修复引入的失败，不偷偷恢复该候选。

## 重放与评分

- 不再调用规划模型。重放第18节已执行的GPT-OSS、Mistral以及GPT-5 medium输出，每项目五个评估里程碑、两库、两做法，共180个不同旧候选；每个修复条件分别重放。读取原最后可执行输出，无可执行版本仍计失败。代码继续可调用冻结编译器或覆盖文件，方案保持原JSON不变。
- 另重放每规划者task-20最后可执行方案，固定用于五个任务；每条件90个比较。两条件共540个评分比较，按项目、任务、完整文件映射去重执行，记录共享评分路径，不将复用当独立样本。原始基线按同样里程碑从已存评分提取。
- 官方断言不变，沿用钉住的Playwright1.57/Chromium1200、30秒用例、5秒断言、一个worker、无重试、首个决定性失败后停止。使用独立harness目录；calculator/table最多六并行，BOM串行，全部项目依次执行。新环境先对三项目的上述开发/评估里程碑参考页校准；任一失败先查基础设施，不把错误反馈给模型。
- 五个开发检查也在冻结之后对两种新库统一复评，作为单独开发分数，不混进评估表。原参考页、冻结文件、模型输出、编译产物和原始报告均留哈希。不根据新评估成绩修复、选库或重抽。
- 同页复用可能减少评分时序差异；新旧分数仍可能有环境波动。各条件中与原文件映射完全一致的候选作单独一致性检查。主表保留所有观察，不能挑高分重跑；未完成/基础设施错误与模型失败分开记录。

## 可回答与不能回答

若固定方案在修复库上改善，证明这些具体输出的行为可因实现干预改变；不能据此把所有原失败都说成库错误。对照review可检验反馈相对额外生成机会的增量，但单种子、不同响应长度、开发配置选择和可能的语义重解释仍是限制。重放不是规划模型见到新库后重新生成，不能称新的生成成功率；所有目标需求原已对建库者可见，也不是非模板组合迁移。库接口学习、广泛迁移与完整代理实验仍在TODO。
