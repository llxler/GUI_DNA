# Web-Bench 历史部署模型的公开建库迁移

2026-11-23 在生成前登记。每份页面只跑当前任务的上游测试。每个项目、部署模型、目标各从零生成一次；同模型的不同建库者共享这一份直接生成。项目级建库看完整公开需求，直接生成和规划只看当前前缀、公开起始工程和资源清单；规划另外看到库声明、说明和首例。独立首响应，无行为反馈、代码修复或按成绩重跑。AI 建库成功后才向对应规划模型发送部署提示；准备失败及未返回的请求分别列出，另报两组都有返回的同目标配对。只按原模型和目标选择任务，这一新部署协议与历史实验单列。

- 部署模型为 Mistral Small 3.2 24B 和 GPT-OSS-120B，各自账本敞口最高 3.50 美元。本轮建库费用由独立的父研究记录。09:24 UTC 以后不再发请求。
- 两个模型均部署 dom1、form、calculator、table、bom 的 1–20 题，分别用 GPT-5 与 Claude 两套新库。GPT-OSS 另测 draw 的 4、8、12、16、20 题及两套库。Mistral 另测 svg-chart 与 expression-editor 完整需求协议的 1–20 题及 GPT-5 库。SVG 的五个里程碑是新协议的可识别子集。没有重新运行旧五题协议；编辑器留出、16k/32k Canvas、Flex、GPT-5 规划、TodoMVC 和 WebApp1K 也都不是此阶段的复测。
- 优先完整形成 table 的配对，随后其他项目按注册顺序循环。从零输出一份完整文件列表；禁止改写公共资源。计划返回所有具名控制值，服务端启用严格 JSON Schema，本地再验型；如有回复但 JSON、接口或编译无效，在预定目标上计失败。上游确实没有模型返回的 429、408、502、503、504 可在独立预留下一次重传，保留所有原预留。其他未结费用保留。API 的 max_price 和输入字节上界控制每笔预留。参数不足的提供商直接跳过，不回退成另一模型。各建库者、模型、目标和账本分别记录；不累计共享对照。
