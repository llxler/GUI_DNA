# 在公开 TodoMVC 宿主上先实现完整控制器，再提取有限选择

表格研究结束后登记的最后一次跨域开发验证。使用此前已登记的全部八个 TodoMVC 公开需求子集和同设置的 Qwen3.5-9B 自由生成基线。两个新库分别用 20261124、20261125 种子，所有结果独立列出。基线八个响应已封存，本阶段不重复生成或挑选。原官方测试、隐藏断言、已有成绩和参照控制器均不进入任何模型请求。新增预算上限 0.80 美元，每笔请求以独立预留控制；05:18 UTC 停止新调用。

1. 用原生研究中从零生成的同一系统提示、原始 JavaScript 源码交付方式及 8192 输出上限，输入这次完整的公开 spec 和 shell contract。没有预置配置项、配置变量或候选接口。在真实不可变宿主中检查语法，加载，init/reduce/select 三个函数；通过界面添加一个公开测试用待办，检查 select 可见、localStorage 的公开存储键，重新加载页面后仍可见。若未通过，只将该公开错误送回同一模型修复一次。注册后的选择是首个通过准入的控制器；此后冻结，成为原始固定页。
2. 对两个合格控制器各从其实际 JS 提出最多三处二元语义选择，提交唯一原文、局部替代与两种行为说明。通用组装器复用表格研究的原文本位置替换，不得改宿主或重写应用。模型同时用公开事件和 view 字段设计一个至多四步、可复验的行为观测。两种行为各用两个全新页面运行完全相同的事件序列，只有末状态稳定且不同、互不重叠、所有新增组合通过公共宿主及添加/重载检查的选项才保留。一次提案格式或公开验证修复只处理被拒名额。无合格选项时逐题方法记失败、仍评测原始固定页。原控制器准入失败时两臂记无效，服务中断缺测单列。
3. 选项冻结后，同一模型针对八个公开目标分别选择，输出只含 original/alternative，原件不变。两个库的固定页和所有方案全部封存后，才执行对应的原官方任务子集。披露新增建库/选项与部署开销、真实失败、缺测、固定/逐题配对及共用从零基线。在宿主公开约定中，未启用功能的事件不会被试题分派，完整固定实现可能通过多个需求子集。该设计同时评估实现和配置的实际贡献。
