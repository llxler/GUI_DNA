# Gemma 对可验证 TodoMVC 控件的独立建库、配置与从零对照

本轮预登记 2026-11-24 两份独立 Gemma 3 12B Instruct 库（初始种子 18271 和 76151）及全部八个 TodoMVC 目标。在已经知道旧阶段相关结果后提出。只给建库者完整公开功能描述和公开宿主合同，模型自己命名一至六个布尔键，交付裸 JavaScript，既声明 DNA_CONFIG 的原始默认值又用它控制真实行为。从零生成按目标接收相同宿主和该题需求。所有单文件建库、直接输出和修复都用同一模型、提供商、温度 0.25、4096 输出 token 上限，设置实际请求 seed。Gemma 也负责逐题配置，使用同温度及原生布尔 JSON Schema。规则只负责验证和绑定已有取值。

接受同一公开源码封装，包括合法 JS、完整代码围栏或 source 字段，依据相同的语法树提取完整 window.candidate 赋值。原始有效程序的默认行为逐字保留。建库独立使用此前冻结的 16 个公开状态、事件、视图及存储检查。从零使用其中与该题公开需求相符的子集。对解析出的每个实际布尔键，在其余默认值不变时测试另一个取值。只有两个端点各自重复两次、同一项公开检查的观测稳定且出现相反判定、两边都能够返回实际值，才可声称该键有行为差异。错误或抖动不作证据。公开探针用普通 JavaScript 上下文与内存 localStorage。默认检查失败，或没有任何经验证的键，允许同一模型查看原答和失败的公开诊断，整文件修复一次。直接代码也在未交付或公开检查有失败时允许同样一次修复。各臂均须保留全部已通过的公开检查；有已验证键的库还须保留其旧行为见证。只有新增交付、增加公开通过或增加有见证的控件时才接受修复。一次真实返回后不能重抽较好候选。

对每份初始及最终的库都分别测同模型逐题方案、固定默认。相同源码、菜单、种子、题面的规划可共用同一份响应。模型只看当题需求、实际验证键、两端观察，未检测出可用键时单列固定默认，严格配置流程计失败。模型缺少响应、可观察但格式失败和未准入区分登记。两个库与共同的八份原始/修复后 Direct 使用完全相同的当前任务及宿主。先冻结全部原始响应、配置与候选，再统一运行原官方测试。逐题资料、分母和预算分开记录。

OpenRouter 仅选择最新登记支持 seed 与结构化输出的 DeepInfra Gemma 路线（输入/输出每百万 token 顶价 0.08/0.24 美元）；单独账本最多 0.65 美元，11:45:40 UTC 之后不发送新请求。每种请求在无可见返回的网络中断、限流或服务错误时至多另预留一次，保留未知预留；模型已经交付的回答不重抽。脚本保存实际 provider、返回模型名、seed、generation id 和 usage。建库 A、B 依次独立，不互相看实现和检查结果。不向外部模型发送任何官方成绩。
