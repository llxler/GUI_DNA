# 按模型实际交付的 TodoMVC 源码绑定配置

本次是对历史六个建库模型的离线开发诊断。已看到部分回复的外层格式及历史结果。沿用每个模型首次收到的完整建库回复、八份从零回复、相同宿主页和当前任务评分器。每个模型、每个目标都保留。新增调用和费用均为零。此前的严格 Self 和 Direct 独立保留；新方法的目标选择由确定性程序完成。

1. 固定全部回复与代码哈希，再封存新页面，之后评分。对从零和库都先读 JSON source，其次读首个含 window.candidate 的完整 JavaScript 围栏或裸源码。先解析整段；整段因尾部元数据语法错误而不可解析时，允许截至最近的、独立完成 window.candidate 赋值的顶层语句末尾。不得补写行为或尝试多个候选挑分。无内容的已收响应计失败，未收响应计缺测。
2. 库若有 JSON 接口，采用模型给的首例与源码。若交付独立脚本，解析唯一的 DNA_CONFIG 布尔字面量（可嵌套于函数），只替换该字面量，首例使用原值。允许模型声明公开规格中的常驻 core 加六种可选能力。记录脚本在声明以外是否实际读取 DNA_CONFIG；写出对象未必意味着实现可配置。已有 JSON 的同域作用域绑定沿用原宿主。
3. 从各目标的公开需求正文查找建库公开规范里的完整句子。模型的配置键与公开功能名忽略大小写、分隔符和开头的 enable/enabled，唯一匹配则按该组需求是否出现取值；陌生键保留首例取值。规划代码不可读目标编号、features、官方测试或成绩。另跑每库固定首例。四列逐题配对：历史严格 Self、同模型对称解析后的直接代码、从原回复恢复的库加规则、固定首例。保留原严格 Direct 单列，以辨别仅放宽交付格式的收益。
4. 必须在全部候选封存后运行同一官方当前任务测试。候选源码、目标均完全相同时可重用有哈希的评分。结果只代表这些冻结回复上交付与绑定的变化。独立新建库、学习新行为和逐目标模型规划需另行采样。
