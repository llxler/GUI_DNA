# 从公开状态合同修复 TodoMVC 模块和从零控制器

此阶段在首次事件建库的官方成绩对本阶段操作者仍未知时提出。只使用已有两批模型模块、其冻结配置、同一模型八份原从零回复、宿主暴露的状态/事件/视图合同和公共需求。先冻结公开检查与修复策略，生成阶段没有官方测试、分数、参考源码或历史解法输入。该阶段有人工决定的事件边界及通用持久化分发器，属于开发性跟进。

每个公共检查均从独立的普通 JavaScript 状态或模拟 localStorage 起步，运行候选的真实 init、reduce 或 select。公开检查覆盖空/非空存储初始化、增添与空白输入、持久化的条目顺序及字段、视图结构、单项/整组选中、开始编辑、保存、取消、清理、路由与计数。真实分值与简单布尔条件回传。建库以冻结的全开控制器执行全部公开检查；每个从零控制器只执行其公开目标所要求的检查。两臂均给同一模型看原候选、相应公开合同和实际失败；每个被对应测试点名的函数最多一次替换、每个有任一公开失败的从零文件最多一次替换，均不允许重抽。函数最多 512 输出 token，从零文件最多 2048，贪心生成，沿用原本地模型和原代码提取器。模型只返回完整函数或完整控制器，不向模型提供修复参考实现。

所有函数候选基于同一份初始失败清单生成；按原协议列出的函数顺序尝试替换。每次使用全套公开检查，只有严格增加通过数且保留所有原有公开通过项才接受。整文件从零修复使用完全相同的接受规则。未通过语法、退化或无改善都恢复原字节。直写未交付代码也可在同一机会下重写。所有接受、拒绝和实际消耗均保存。

对每个库继续使用原模型的八份真实计划，以及原有全开和关闭可选事件两个对照。不依据检查重新规划或调整开关。原始、公开修复后的从零全部八题都保留；每个模型每个任务的旧/新库原方案和两个固定方案都封存后，才调用原当前功能 Playwright 评分器运行。不同阶段或组只有在目标和候选字节完全一致时才能共用评分。执行八个现有公开任务，分析时区分公开诊断与官方成绩。全程本机运行，无外部 API。
