# TodoMVC 公开状态反馈的配对修复

沿用两套本地 Qwen2.5-0.5B-Instruct 的十二个事件、初始化、视图及持久化函数与八份同模型的从零回复。给两条流程同一组公开状态转换检查，建库按出错的函数修复，从零按该题的完整控制器修复。两臂均要求公开检查严格改善并保留每条已通过结果。既有配置和宿主未改。[预先冻结的检查与接受规则](PROTOCOL.md)

库 A 在十六项公开检查中从 2 项提高到 3 项。十一项函数提议中只有清除已完成项的修复获准。库 B 的十一项函数提议均未带来无回退改善，仍通过 1 项。对每个从零目标给相同的一次公开修复机会，八份改写均未获准。A 的原始视图对公开规范中的布尔 completed 值调用 trim 并报错，两份库的原新增操作都没把第三项加进列表。单个事件的改善仍须在整份作业的官方功能测试中重新检验。

在相同八个官方任务上，A、B 的逐题方案分别从 0/8 到 0/8，两套库的全开和关闭可选事件对照也各为 0/8。共享的八份从零生成在修复前后也均为 0/8。共封存 112 个方法－任务位置，包括两份库各自修复前后的三种部署对照和一份共享直接对照的两个版本；按目标与源文件去重，共有 53 份有效当前任务浏览器记录。公开清理操作的改善未使任何一个完整官方目标通过。[原始、修复后和逐例公开检查记录](result.json)

该阶段实际使用本地模型生成三十次。两库各十一份函数回复，分别使用 8,738 / 1,366 和 9,012 / 1,470 输入 / 输出 token。八份从零回复共 14,802 / 6,301 token。与旧阶段共用的首次生成与规划成本另计。新增外部 API 费用为零。

检查已发布的逐题分数和公开接受判据使用如下命令。

```bash
uv run python -m studies.public_library_transfer.self_refinement.todomvc.event_modules.feedback.run check
```

有已冻结的原建库模型答复、本地权重和浏览器环境时，依次执行同入口的 `register`、`generate`、`score`。前两套库的相同目标和相同文件可以用同目录的 `reuse` 模块在核对源文件字节、原官方断言与报告哈希后共用旧收据。原建库与修复后均按同一目标与同一宿主执行，文件无法交付计为流程失败。
