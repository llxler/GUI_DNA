# Web-Bench 问卷组件的独立建库与组装

在 Web-Bench `form` 的 20 个官方当前任务上，用 `openai/gpt-oss-120b` 独立建库两次。每次先生成 `Question` 基类，再把本次实交的基类代码传给八个子类。模型也生成 `Contents`、`Survey` 和样式。逐类公开检查会在浏览器中导入具名类，实例化并操作控件，失败允许一次修复。预登记的输入、成本上限与评分边界见 [PROTOCOL.md](PROTOCOL.md)。

同一模型在每套库上分别生成 20 份任务方案，以及一份看到全部公开需求后生成、用同一页面评全部目标的固定方案。无库组逐题从头编写源代码，使用同一起始工程，并可使用同一份公开组装器；对已要求的题类，同样执行公开检查和至多一次修复。两套库共享这 20 个无库候选。逐题方案使用的数据结构及编译接线来自研究者：组装器实例化模型写的类，并在计划要求时实现导出按钮与存储操作。模块、方案与无库页面的实现分别计费。

独立公开控件检查中，库 A 从首稿 8/9 种修复至 9/9 种，库 B 首稿即达 9/9 种。库 A 的开放题在构造控件前尝试设置必填属性，公开浏览器报错后模型修正。实应用的两个失败来源在此分开：两套库均在第 11 至 13 题的必填状态切换上失败；第 20 题的两份逐题方案都将公开要求的 `exportData` 选为假。库 B 的固定方案选择导出且通过第 20 题。较宽解包后，从零额外通过第 4、20 题；两套库各自通过的题全部也被同一份从零组通过。此前 GPT-OSS 问卷库有 8/9 种通过同一类型检查，其原逐题成绩为 10/20，旧阶段的建库方式及从零组另列。[历史类型探针](../form_registry/README.md) · [历史逐题分布](../../../results/self-failure-diagnosis-20261124.json)

98 个请求共结算 $0.034539，未知预留为零。库 A、B 的建库与公开修复分别为 $0.003440、$0.003076；逐题规划分别为 $0.002858、$0.002717；各自固定方案为 $0.000151、$0.000205。从零共享组初稿 $0.013369，公开检查后的 11 次修复 $0.008723。离线空白复验无新增费用。

`result.json` 按独立建库保存逐题通过情况、同一任务上的通过差异、公开控件检查及各阶段成本。`direct_first` 为从零初稿，`direct` 为公开检查及至多一次修复后的交付；没有得到响应的任务独立标记。每个分母来自同一组双方可观测的官方任务。只读复核使用以下命令。

```bash
uv run python -m studies.public_library_transfer.self_refinement.form_components.report check
```

保存了本地 `artifacts/form-independent-components-20261124/` 原始回执与官方浏览器评分时，使用 `report check-local` 核对代码、账本、候选文件、原始评分与发布 JSON。公开报告可在不读取原始响应的环境独立检查。

个别已完成的回复在外层两个 JSON 括号间写了字面量 `\n`。其中的源码可原样恢复。单列的[空白复验协议](whitespace/PROTOCOL.md)对从零、逐题方案和固定方案的每份回复采取相同解包，不新增模型调用。公开控制通过后仍按原规则在首稿停止；真实截断的字符串继续记为无效。对应命令为 `uv run python -m studies.public_library_transfer.self_refinement.form_components.whitespace.run check`。
