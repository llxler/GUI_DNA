# 原生文件写入阶段的传输恢复

原运行在第二批第四次文件编辑的 HTTP 502 后封存，原库、固定页及逐题行均缺测，保留未结算的原请求预留。此清单在取得任何有效最终页面和官方成绩之前登记。恢复的唯一变化为传输层：重用全部已结算的原始响应和已完成批次的公开检查，通过原文件路径、请求内容、响应和修复回执的 SHA-256 核对身份；对于 429、临时 5xx 或连接超时，在原定相同消息、模型、参数、输出上限下总共最多三次传输尝试，其中既有 502 已计一次。每次新传输都是新的账本预留。认证错误和无法归类的中断依旧缺测。

原方法的模型、冻结接口、五批需求、每文件写入/语法校验、每操作最多一次针对可见格式问题的模型修复、最终公开检查、20 次部署和官方协议保持原状。已通过的公开写入和截断前收到的格式无效响应全部按原样重用，不选择较好的重试结果。只有无响应的瞬时故障才触发重新传输；新过程中收到可解释的响应后不会再为同一次传输重采。若最终建库中断则同样报告缺测，不把部分库当作完整库。

恢复使用独立账本，上限 1.96 美元。文本编辑原敞口 0.001823 美元、原生工具首次原敞口 0.026570 美元另列，合计预算不超过原有 2 美元。旧账本和未知预留不动；截止时间仍为 2026-11-24 05:18 UTC。本次恢复是同一包的续作，不计作独立重复。
