# Web-Bench 问卷类型注册与独立挂载探针

本诊断在看过历史建库准入和源码格式后登记。每个模型固定使用原建库流程最后一次实际收到的回复，包括空白、截断和整包不合规的回复；不在两次尝试中择优。仅解析模型可见答复与原公开起始工程。允许归一相对路径前缀，读取完整 JSON 或截断回复中已结束的模型文件记录。研究者只使用公开需求指定的类型、参数、DOM 语义，生成中不读取参考实现或官方测试。构造器、控件与交互逻辑必须来自模型。
 
原始接口读取对应文件的同名或默认导出；若无独立模块，则加载模型的整体脚本并查同名全局类。第二个接口使用语法树定位实际存在的类：给同文件同名顶层类补充缺失的具名导出，将已有类的值登记到隔离浏览器实例的注册表。可保持闭包语义，只加读取绑定的接线，不移动实现，不改变类、构造器或处理器，不补缺失类型。壳上有原公开空白表单，探针逐个实例化并把模型返回的 root 挂入该表单。浏览器只允许本次生成的本机资源，每个类用独立页面。冻结全部源文件和探针后才启动浏览器。
 
每模型每接口均检查九类：基础 Question 和 SingleSelection、MultiSelection、Open、Rating、Ranking、Nps、Likert、DataQuestion。分别记录可调用构造器、连入 DOM 的根、公共标题结构和类型特有的一个小验收。基础类核对标题、主体和命名的 fieldset；单选/多选实际点击并检查选中状态；开放多行写入文本；评分点击并看具名值；排序只检查三项呈现和初始顺序值；NPS 点击七分记录值；Likert 在两行分别选择；DataQuestion 向 email 控件写入邮箱。不评价未实现的交互，不据此生成官方 20 题成绩。此处测的是已有模型源码能否作为可组装类独立复用；没有直接生成对照或新模型调用。
