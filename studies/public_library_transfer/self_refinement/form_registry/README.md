# Web-Bench 问卷构造器的公开接口检查

从每个模型历史流程的最后一次建库答复读取九类组件，逐类在原公共空表单中实际构造并挂载。每个类型有一项公开检查，包括选择、输入或读取控件状态；基础类核对标题和主体，排序类核对三项及初始顺序。只给已有类补上可见的导出和注册接口，再在独立页面重复。共 126 次浏览器页面探针。此处单位为问卷类型，未对本研究的页面运行官方二十项任务，也未调用模型。[冻结协议](PROTOCOL.md) · [逐模型和逐题型记录](result.json)

| 原建库模型 | 原接口可挂载 | 公开已有类后可挂载 | 原接口通过类型检查 | 公开已有类后通过 |
|---|---:|---:|---:|---:|
| Qwen3-Coder-30B | 9/9 | 9/9 | 8/9 | 8/9 |
| GPT-OSS-120B | 8/9 | 8/9 | 8/9 | 8/9 |
| Mistral Small 3.2 | 0/9 | 9/9 | 0/9 | 6/9 |
| Qwen3.5-9B | 0/9 | 9/9 | 0/9 | 1/9 |
| Gemma 3 12B | 9/9 | 9/9 | 0/9 | 0/9 |
| DeepSeek V4 Pro 0813 | 0/9 | 0/9 | 0/9 | 0/9 |
| DeepSeek V4 Flash | 0/9 | 0/9 | 0/9 | 0/9 |

Mistral 的实现可提供单选、多选、开放、矩阵量表与邮箱控件，补上模块导出便可调用。Qwen3.5 的九个类都有可挂载根节点，只有基础空题通过对应检查。Gemma 的构造器可实例化，组件独立挂载时未形成公共题干结构。GPT-OSS 缺少数据输入类。DeepSeek Pro 的最终可见答复被截断，Flash 的最终回复无可见内容；均没有抽到完整候选文件。这个探针直接刻画组件独立复用能力，完整应用如何调用它们另需项目级评测。

```bash
uv run python -m studies.public_library_transfer.self_refinement.form_registry.run check
```

如有本机冻结收据，先执行同入口的 `register`，再执行 `run` 重建浏览器结果。本机 Chromium 的动态库位于仓库的 `.browser-deps/usr/lib/x86_64-linux-gnu`，重放时需加入 `LD_LIBRARY_PATH`。只读核查使用仓库内 JSON 和源码。
