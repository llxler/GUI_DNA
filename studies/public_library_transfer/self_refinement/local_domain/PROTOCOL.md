# 本地小模型的计算器行为注册表

项目限定为 Web-Bench calculator 的 20 个当前任务。使用本地 Qwen2.5-0.5B-Instruct 的同一权重、FP16 和 GPU。研究者预先选择计算器域和按钮注册表、共享显示状态的绑定结构。模型自行列出新增标签、编写每个按键的运算、界面逻辑及一种二值行为的两种实现。这是有人工领域脚手架的同模型建库，不能据此外推到自主发现架构。该项目没有来源同等的人工库对照。设计只使用公开初始化、起始 HTML 和完整需求。隐藏断言、参考实现、已有浏览器成绩和其他模型源码均不交给模型。

- 独立两次建库，种子为 1151、3503，温度 0.45，top-p 0.9。按连续五条需求分块抽取需新增的按钮；保留模型写出、公开原文出现、起始页尚无的标签。公共绑定器只负责在面板增加按钮、读取/写回起始页显示状态和保存共享对象。模型为每个标签编写 JS 表达式；只允许一次基于解析器错误的修正。两段独立生成的 JS 分别实现外观与界面状态、记忆与历史控件。模型另为一个自己提出的公共行为分歧生成两段设置代码。二值说明格式或设置源码的语法错误，各只允许一次格式修复。从公开加载记录两种取值的错误，出现错误如实保留。所有输出保存在本地。
- 每个目标只给规划模型截至本题的公开需求和库行为说明，greedy 打分选 A/B；A 是固定首例。B 另作固定页控制。记录固定两端与逐题选择各自通过项。若模型未提供有效的二值说明或语法有效的两种设置，方案流程与两个对照按构建失败计零。模型说明、按钮实现及组件均禁止按任务编号分支。
- 强化直接对照：为每个目标全新生成完整原始 HTML，使用相同模型、同一 starter、相同需求前缀、greedy、上限 2,048 token，包装语法另有容错（允许 Markdown fence）。原始历史 JSON 格式从零结果若需要可单独查阅。不得选择基线协议或较好重复。自建库会额外读取全量公开需求并分多次生产代码。
- 所有生成及固定页先封存，随后以原有浏览器运行环境、原版单一当前任务文件逐项评分。每个种子均报告总数、与直接的逐题配对、页面交付、两种固定配置。若项目载入与模型输出均可用，研究代码与协议、输入、模型配置、权重散列和所有生成/判定文件来源一并留存。缺失与程序性故障独立记录。全程不调用远程 API。
