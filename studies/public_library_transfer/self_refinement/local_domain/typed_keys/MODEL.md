# 让模型选择每一个按键的运算

在读取本研究任何官方通过数前，额外登记单因素对照。与受限语法组复用完全相同的两份界面模块、按键目录、A/B 排序页面和同一逐题模型选择。取消按键名称、字面表达式到运算的确定性链接。对于目录中的每一个键，模型从同一整套受限表达式中选出一个，运算值均重新生成。保留两份独立取样。共享的程序载体、候选语法与任务输入来自既有协议，继续将确定性链接器和从零作为独立对照。此组检验此前九个可直接链接的按键在交给模型时是否仍能工作。

使用相同的本地 Qwen 权重。在公开按键名、显示标签及首次引入的公开描述之后，提示补全一个 JavaScript 的 return 表达式。限定回复为全部注册语法中的一个表达式，逐 token 以温度 0.45 在合法的下一个 token 中采样。种子为 7253、8039 加上目录位置。数学、算术和记忆运算对每个按键都可选；不按名称缩小候选集。不提示参考答案；小样例仅演示无关运算和语法。已生成的两个附加面板、全部逐题选择及 Direct 逐字复用。两个 A/B 固定页、选取页和直接页比较原版同一当前任务。CPU FP32 推理；如资源受限可在计算机空闲时运行，结果单列，不能替换主协议。
