# 按单功能生成 JSX 的 Duo 配对复验

在新调用及成绩之前登记。两域 blogging、taskmanagement，所有 15 个公开单功能和此前固定的十个组合。Qwen3.5-9B、GPT-OSS-120B 分别作为建库者、规划者和从零生成器。两次独立库 A/B 使用不同种子、不同请求及独立文件。每个组件单独生成，输入只含该单功能标识与公开单功能 Jest 规范。不得读取其他实现。每个组合的 Direct 独立从零读取完整公开组合规范。本研究样本的四十个组合用例与公开单功能用例重合；结果只检验已知功能的组装，不能证明隐藏功能泛化。

每次源码生成均请求一份完整 JSX 默认导出；两组共用相同静态提取、依赖限制及 default 声明修正器。完成第一个合法模块后，运行独立公开单功能文件的两个用例。无合法源码或单功能失败可向同模型返回一次限长的单功能错误，保留首轮与修复结果。修复返回合法源码时采用修复稿；未返回可解析源码时沿用首个有效稿。虽未通过公开检查但可解析的稿件仍保留并进入最终评测。没有收到过调用返回与已收到但输出不合法分别计入缺失与流水线失败。对于每个 Direct 候选同样在其两个公开单功能测试文件各运行单一完整候选，失败同样可修一次。单列原始 Direct 以及经相同公开反馈修复的 Direct。没有任何组合评测结果进入修复。

每个库通过各功能的公开标识暴露组件，供同模型逐目标一次选择两个标识，输入为可用标识及公开组合需求。两个对照分别按组合中明示的单功能名字装配、固定复用该域按字典序的头两个登记标识。选中缺失或非法模块分别保留缺失或判流程失败，不自动换成其他选项。沿用冻结 React props 转发装配器。首次和修复后模块成本、部署、直接修复成本分别报告，两次库报告相同的十个公开目标及同一份新 Direct 对照。另外记录初始与修复后的独立单功能成绩。所有两模型、两套库、Direct、全部计划与产物同时封存后才执行官方组合文件，四个断言全过才计一题通过。
