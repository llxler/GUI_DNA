# 依赖顺序建库的代码模型复验

预先选择 Qwen3-Coder-30B-A3B-Instruct，在公开 Web-Bench 表格项目同一批二十个目标上独立建两次库。选用该模型是因为历史记录已有可交付页面，可以观察实现和接口错误。两份库都进入报告。所有本轮调用固定在公开登记时支持原生结构约束的 SiliconFlow 路由，temperature 0.2；该路由没有声明 seed 和 reasoning，全部省略。两次建库不共享模型回答、代码、探针或配置。新增上限 1.30 美元，2026-11-24 05:18 UTC 停止新请求，先核对余额。

1. 只给模型公开起始工程、可见资产、需求和由其字面提取的必须文件名。模型自行设计有限控制及首例，分配持久状态、交互和模块职责，自行设计一个浏览器交互检查。先设计依赖先后的源码顺序。允许集中在一个额外公用模块实现共享状态，其他公开指定路径按设计暴露接口。程序只把模型提供的有效路径去重并补全字面要求的文件，入口总是最后；无人工控件、目标分支、参考实现或评测反馈。
2. 按顺序逐文件调用同一模型。每次给此前库的真实源码以及 Node 的 ES 模块静态链接结果和真实导出名。模型可引用已经交付的依赖。新文件导致静态链接报错时，整库最多两次即时原文件修补。若此时依赖尚未交付，可以在完整图中再次检查。全部源码到齐后运行公开浏览器加载和模型自己的交互；完整图有错、浏览器加载有错或探针不过时，允许一次由模型明确指明路径的多文件修补。若初版可加载且链接正常，修订导致失效则保留初版。最终需要可加载且完整图链接正常；探针结果作为独立证据记录。没有根据任何官方分数进行修补。
3. 新从零组对每个目标提交整页代码且不读取任何库；两库各自在同一组公开目标前缀上一次提交配置。同模型、同路由、同 temperature、同一 8192 输出上限及原生响应格式，用不同 schema 分别表示文件集合和计划。每库另冻结首次示例页。封存三组全部候选后，在同一官方当前任务文件上分别评分 Direct、Self A、固定 A、Self B、固定 B。每个任务使用同一个 Direct。逐重复报告原始历史对照、新对照、缺测、同题翻转和分阶段费用，包括收到的无效交付；不挑选较好重复。
