# 依赖顺序建库的传输续接

前一登记中两份独立库都在某一模块收到 RemoteProtocolError。已观察到的原始设计、源文件和直接生成回答按哈希原样复用。来源阶段完成全部候选封存后登记续接。两阶段合计敞口不超过 1.30 美元，以原账本实际费用加未知预留为起点，不把中断算成零。仍于 05:18 UTC 停止新请求。

各逻辑请求沿用同一模型、路由、消息、采样参数、token 上限、schema 和文件顺序。原先已经收到有效传输收据的一律复用，包括任何内容质量问题。原先缺失的传输才可发送同一请求；每个逻辑请求合计至多三次实际传输（含原有未知尝试）。只对传输中断、超时、HTTP 429 或 5xx 退避后重传，间隔 2 秒、6 秒。整阶段通过一个跨进程锁，最多一个请求等待服务端返回。没有接收的重发保留全部未知预留。登记时只有 SiliconFlow 满足同一模型、原生 schema 和 temperature，全程固定此路由。原始阶段单独保留；继续缺失则如实报告。

单独封存续接后的两个建库重复与 Direct，复用相同的本地编译与官方当前任务评分。最终报告区分沿用逻辑响应和新增账本请求，重复使用的 Direct 只收费一次。开发中仅使用公开模块导出、启动情况和模型自定交互。该续接没有重新抽取任一已收到的模型回答。
