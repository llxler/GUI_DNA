# Staged self-built behavior libraries

Freeze the registration and public inputs before any model calls. The table development pilot uses the twenty numbered public Web-Bench requests and two separate frozen builders/planners, GPT-OSS-120B and Qwen3.5-9B. The deadline for new requests is 2026-11-24 05:18 UTC, with $2 reserved for each route. Independent transfers must register their dataset and allowance separately. Each model sees public starter, assets and task descriptions only. Existing benchmark outcomes motivated the development project and selected backbones; official checks and prior implementation are inaccessible to all model prompts.

1. The builder designs semantic controls, their first documented example, one public interaction probe, and the boundaries and interfaces of its own source files. It may list up to sixteen file paths to preserve names required by a public brief. The public HTML stays in place. The starter's JavaScript entry point mounts the app and uses the builder's modules. A CSS and module implementation request per non-entry file uses the public project and interface contract. The entrypoint is generated last with the complete received modules. Each output is raw source with an optional single outer fence. No agent supplies project-specific behaviors. Unchanged public starter paths are copied. Controls are fixed strings accessible as globalThis.APP_CONFIG and HTML attributes.
2. A single additional builder call per library can correct an invalid manifest or a materialized implementation that fails a public page load or the model-authored interaction. The public probe dispatches the declared event to its first matching element and checks the requested visible selector. Browser load is required for library admission. A failed advisory probe is recorded. If a repair for a probe-only failure produces an invalid or non-loading library, retain the already-loadable initial one. No repeated candidate generation, cross-model assistance, or official-test-based repair. Missing transmissions retain reservations.
3. Freeze the library and its first/example configuration. Separately ask the same model once per public task prefix for its configuration. Accept a full named map of in-domain values or a full ordered value list, optionally enclosed in a single plan field. Bare booleans map to their textual equivalents. A received invalid manifest/implementation fails the registered twenty targets for that arm. A missing construction response yields missing dependent targets. Received invalid plans fail individually; missing requests remain missing.
4. After all twenty plans for a builder have been sealed, run the unchanged official current-task file on each planned page and on the unchanged first example on the same targets. Missing inputs and scoring errors are recorded separately. Pair original no-library Direct and original Self by exact project, backbone and task. Report attempted and received denominators, new Self and new fixed first, all four individual task outcome vectors, gains/losses over jointly observed targets, receipts, and separately attributed build/plan costs. Do not pool transfer data, repopulate an existing evidence cell, or select a better run.
