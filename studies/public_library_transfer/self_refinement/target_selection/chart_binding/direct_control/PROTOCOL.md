# 对无库响应开放相同的格式恢复、接线与公开修复

这是在检查已封存的原无库调用状态后追加的敏感性对照。Qwen3-Coder 原记录显示全组均因缺少外层 files 字段被拒绝；DeepSeek Flash 多数响应没有可见文本。两者均预定全部 20 个旧目标，不增加模型调用。两份库的独立观察与成绩照留。不根据无库成绩添加修复。

用历史相同解析器读取各目标已保存的响应。原来合法的唯一 files 对象照用；若整个 JSON 本身是非空的“安全文件名 → 完整字符串”映射，则仅补外层 files，保留全部源码字节。否则保持失败；不补全文本或掩盖供应商缺失。使用原来的路径/内容白名单、公开 starter 覆盖和资产挂载。单独评分这份仅恢复文件格式的无库页。

每份原响应也可用与供库组完全相同的启动接线与一次公开作用域修复。先保留已有入口、挂载和 draw；入口未挂载且具有同样形态时应用同一个已冻结的接线函数。对接线页进行相同公共运行观察两次，有确定 ReferenceError 且符合原限定修复器才移动同一组已有表达式。不引入图形、库实现、参考源码或人工针对某一份无库代码的修正。把原合法、等价恢复、无可用内容、公开错误、修复和未修复分别记档。所有目标均接收同一回放流程，整个批次与全部页面哈希先封存，再运行任一无库页的官方评分。最终将原严格 Direct、补包装后的 Direct、等价接线修复后的 Direct 与旧 AI 库和人工接线后的 AI 库同题区分报告。
