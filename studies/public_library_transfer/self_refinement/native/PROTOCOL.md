# 以可执行接口交付 Qwen 自建库

旧表格实验中 Qwen3.5-9B 的简短接口请求将 6,500 个输出 token 用完，未交付可见正文。本批在看到新评分前指定两个 Web-Bench 项目（表格、问卷）及全部 20 个当前文件。两项目各做两次从头独立建库，同时各生成一次同项目、同模型、同目标的从零代码。每个项目的所有候选和固定首例封存后才取官方评分。保留四套库，包括失败的重复。

通过 OpenRouter 向原来的模型请求关闭额外推理。设计、部署配置和从零页使用 API 原生 JSON Schema，源码按文件输出原文，并在本地重新验证。固定字段名由序号确定，行为、两种取值的语义、首例取值、模块接口和共享状态均由模型从完整公开需求和起始工程指定。逐个实现公开路径中的源码，入口最后读取所有实际模块再装配。允许一次根据公开加载或模型自拟交互检查修复一个或多个文件。修复后仍无法加载则该库失败，不另采样。建库者看不到参考实现、官方断言、已有候选和得分。固定首例在看到评分前由初次设计给出。

从零组仅获得本题公开需求前缀与起始工程，和逐题配置采用相同模型、同一服务参数、8,192 输出上限，各一次；从零组可供任意合法源码路径，保留公开起始文件。建库额外调用、token 和费用单列。各库同自身首例、当批从零、原 Self 和原从零逐题对齐，主结果用五臂共同可判定目标，另报逐臂覆盖、库准入和两两得失。收到的无效产物算失败；传输缺失单列。两套重复使用不同固定种子和独立输入输出目录。05:18 UTC 截止新请求，每项目上限 1.20 美元，合计 2.40 美元。若服务不支持请求的参数则保留缺测。
