# SVG 原始源码交付的离线敏感性

在读取本批任何 SVG 官方成绩前登记。样本为 Qwen3-Coder 对二十个公开目标已经返回的原始 Direct 回答（每题首次及已触发的一次公开修复），以及已交付的两个 AI 库。已知部分 Direct 因主动提供公共资产或在文件标签上添加 Markdown 记号而在原解析时被拒。此次研究检查交付边界。全部原始回答和先前严格成绩永久保留。不得再向任何模型索取回答。

解析规则对任何一方的模型源码均适用。首先沿用既有单文件、裸文件映射、封装映射和明确的 FILE 标签。另接受由井号标题、可选注释标记、强调或反引号包围的独立 FILE: 相对路径行，其下一文件标签之前的首个完整 Markdown 代码围栏为文件原文，忽略围栏前后的外围说明。无完整围栏的原有纯源码文件段仍按原规则对待。对回复中所有位于根目录 assets/ 下的提交项一律丢弃，由只读上游提供准确字节；其余路径按原验证器审核，不自动改写、不补导入、不修复语法、不改变绘图、样式、数据或规划。对既有合法交付优先复用原始源码和页面。库模块从独立命名文件返回，仍保留其原解析结果及公开资产，若存在类似的外层封装会使用同一处理原则并如实记录。

对每个 Direct 目标逐一重新评估原有两个真实尝试。按照原 run.from_scratch 的公开选择条件，首次为默认，只有原触发的后次响应有可交付页面、并符合原有公开改善规则时才替换。若先前无法解析的首次回答在此处已可运行且不触发原公开修复条件，沿用这个首次回答，另把历史上确已收到的第二份回答作为独立候选记录。没有回答继续保留未观测；已收到的无效源码仍记为流程失败。仅对严格条件下未交付而现在有页面，或实际选择的文件散列变化的候选做新的当前任务浏览器评分；与任何旧候选同项目、同任务、同文件散列且评分合同相同时复用其可验证收据。不同交付接收规则不得被写成同一份 Direct 的原分。报告每题接纳与否、丢弃的公共资产名、来源散列、接受的运行页面及只修正包装产生的成绩差异。

二十个 Direct 的两个尝试、公共观察、最终页面全部冻结后，才开始本敏感性的任何当前官方测试。按同一目标与严格 Direct 和各独立库同协议规划/固定来源（原始、仅链接、若完成则含公开异常修复后的阶段）作配对。来源有真实缺失时明确分母。库的各阶段各自保留，共用这份相同的 Direct；不得按官方得分跨库、跨题或跨阶段挑选最优页。保留仅宿主及去除资产题的对照。本研究新增模型 API 调用数为零。
