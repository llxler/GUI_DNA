# 图形生成调用与浏览器类名接口

模型的两份新图表库已暴露同一个公开异常：绘图代码将含空格的 CSS 类名串交给 DOMTokenList.add。按上一阶段既定的公开判据，一份模型补丁虽然让五类数据出现图元，却因遇到更多不同错误文本被拒绝。在未读取本批 SVG 任何官方得分时登记本次只读源码诊断；原阶段已开始自动评分。这是对同一批已知故障的诊断，不是新独立建库。

只在公共载荷确实产生 DOMTokenList 的空白 token 异常时，修正候选 JS 文件里的单参数 .classList.add 调用。参数限无副作用的普通变量或字符串/无替换的模板字面量；传入值是带空白的字符串才分成非空 DOM token，其他值原样传给现有方法。既有类名、绘图元素与算法均保留。只改源码，禁止改浏览器全局或公共资产。库的公开见证取自定点反馈阶段最终全开页；两份库分别在固定页上验证，修正再应用到该库最终逐题页与固定页。从零有两套输入：上一阶段收到的最终页，以及另外登记的宽松交付页（允许丢弃模型回传的只读公共资产，保留起始公共原件）。每套输入逐题用同一异常判据检查。另测原宿主接线。全部页面先封存后执行本诊断任何官方任务。

用同一目标上的成败做比较，两个从零流程分别给出，并报告只要任一从零流程能过的目标数作为逐题择优上界。这一上界不能直接运行，数值只用于敏感性分析。每份库分别报告固定与模型选择、各自独有成败、公共资产题剔除后的计数。保留另外三阶段所有分数、错误与费用。无需新模型调用。
