# 两套全新 SVG 图表库的前瞻确认

ByteDance Web-Bench 的同一组二十项公开需求上，重新从 Qwen3-Coder-30B-A3B-Instruct 采样两套独立的七模块库。研究者提供 public starter 的数据挂载与六个命名类型开关。模型负责基类、六个绘图类与四十个目标方案。建库时可使用公开的独立渲染检查；在这轮调用之前已经冻结的两项接线修复分别处理可唯一确定的父类导入与浏览器实际报出的 classList 空白异常。模型没有看到上游参考实现或官方成绩。[预登记](PROTOCOL.md) · [公开观察器的兼容入口](OBSERVE.md)

每套库分别按二十题报告逐题方案和固定六类全开。两套库共用上一批冻结的、同一模型生成的二十个较宽代码接收从零候选，本次没有新采样从零页面。逐题记录披露旧从零回复和官方报告哈希，两库的每次请求检查真实提供商、唯一标识、出入 token 的回执与账本；建库模块的实际源码哈希可同上批核对。[逐题结果](result.json)

| 同一批官方目标 | 新库 A | 新库 B | 复用的从零组 |
|---|---:|---:|---:|
| 逐题方案或从零，同一组 20 题 | 6/20 | 6/20 | 5/20 |
| 固定六类全开，同一组 20 题 | 6/20 | 6/20 | — |
| 逐题方案或从零，排除仅检查项目资产的第 1 题 | 5/19 | 5/19 | 4/19 |

两套库的固定页各自通过了与逐题方案完全相同的题。库 A 独于从零组通过 6、19、20，从零组独于库 A 通过 12、13；库 B 的对应差集是 5、6、19、20 与 4、12、13。两套独立新库的全部十四份模块源码哈希彼此不同，与旧两库也没有完全相同的源码。公开修复为每套库补上五处父类导入，并在实际触发空白类名异常后规范调用；两份全开页面分别在六类公共数据上产生 328、297 个 SVG 图元。两套的柱状图仍分别有未定义的 `gridYCount` 或对未定义元素写属性的异常。画出部分图元与完整通过该类任务需分别解读。

66 次请求全部结算，共 $0.035689。库 A 的 13 次建库/公开修复用 $0.012251、20 次规划用 $0.004799；库 B 同样次数分别用 $0.013840 和 $0.004799。40 份模型方案均合法，未出现传输缺失。两库各有 14/20 份方案选择六类全开。
