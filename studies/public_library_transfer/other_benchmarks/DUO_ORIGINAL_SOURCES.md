# 以原 WebApp1K-Duo 建组件模型重建有限接口

在已看到订阅建库组结果后发起，新试验独立登记，使用现有 2.00 美元历史部署共用账本及 09:24 UTC 截止时间。模型为原研究的 DeepSeek V4 Pro 0813 与 Qwen3 Coder。每个模型用相同的建库提示，在两个类别各独立生成一次组件菜单，分别只见本类别七或八份公开单功能 Jest 文件；原组合测试、历史成绩和其他模型生成物均不进入建库提示。取首次实际返回，按预定义接口准入。此次无需重新抽样订阅库，也不将单功能修复阶段混入本面板；不合格式的库记为未准备成功。

同一建库模型的两个类别分别封存；每个原规划模型用两种来源各自的菜单，在全部十个原目标上各规划一次。优先分析同名的建库者和部署者，并单列交叉组合。每个规划模型都使用该轮历史部署组中同模型、同公开提示、同温度、同种子和样本号的实际无库代码（每个目标一份）；固定首例在每个目标原样运行。两种模型选择的库接口各自确定，编译器只接受两个枚举参数。将旧按单功能分别生成、允许跨模型挑选原子变体的历史阶段作为独立参照。原有结果不改。

建库和部署请求均为首次实际返回；无模型返回的网络中断最多三次重新申请独立预留，不释放不确定款项。一个端点的鉴权、计费或不可路由状态使该模型停止后续调用；预算受统一账本原子预留控制。两个类别的全部新源文件先冻结，全部组合部署回复再统一冻结，最终才运行官方组合测试。实际成功返回、无返回、接口拒绝分别报告；逐分母披露。测试来源重合沿用同一原样本的独立审计。
