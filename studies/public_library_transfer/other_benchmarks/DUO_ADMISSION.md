# WebApp1K-Duo 公开单功能准入与一次修复

本诊断在查看原订阅组组合成绩后提出。先登记原 10 个组合目标、两类各两套库、原任务选择方案、固定首例和同一份原无库基线的哈希。禁止组合测试、历史组合成绩及人工挑出的故障说明进入匹配或修复提示。建库和准入的单功能输入来自原研究选取的 15 份公开 Jest 文件。这些测试与组合评分用例的内容可能重叠，另作逐用例来源核对。

1. 每个类别和库独立用一个全新订阅会话把公开单功能测试和该库的自定组件说明匹配，每份单功能测试指派一个组件，要求组件与单功能目标一一对应。在看到任何单功能评测结果前封存四个映射。重复、缺失或无效映射记为准备失败；不挑选候选。
2. 单独挂载每一个匹配组件，运行对应的原版单功能 Jest 文件。类别内所有单功能文件均通过才准入。初次全部通过的库冻结原字节；有失败的库由同一订阅模型只修复一次。修复输入仅为公开单功能测试、原库、冻结匹配和自动截取的单功能失败信息。只允许替换失败组件的模块源码，按原 ID 编译，保留所有成功组件、接口、顺序和首例。复验类别内全部单功能。
3. 先冻结全部修复源码与单功能复验记录，再用第一个订阅研究的原 GUI-DNA 方案和固定首例运行全部十个组合目标，按库分列，与原共同直接代码配对。报告准入状态；也展示未能通过准入的有效产物的诊断回放，并单列严格准入政策下成功部署且通过的任务数。原先的 5/10 和 9/10 原样保留。单套库的注册单位是该类别的五个原组合任务。
4. 每个官方组合文件固定有四个 Jest 测试用例，每个公开单功能文件有两个。按 JavaScript AST 识别顶层 test 调用，比对完整测试语句，只将所测组件的 JSX 标签绑定名统一并归一换行；给出匹配用例数、覆盖组合数和去重单功能用例数。不把成分复测写成隐藏功能泛化。
