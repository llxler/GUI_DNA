# 三个 Web-Bench 项目的旧 Self 失败诊断

本分析在原成绩公布后执行。按生成模型、项目和目标连接 11 月 24 日原批次保存的建库状态、组装交付状态与官方当前任务回执。每个可用模型对每个项目只建一个 Self 库，随后尝试为 20 个目标逐题配置。五个因 HTTP 403 关闭的模型只登记于表格和 SVG 两个项目，产生的 200 个 Self 缺测单列。人工库和冻结 GPT-5 库各自每项目复用同一份包。逐目标方法的缺测、构建被拒、配置无效、成功交付页面后测试失败和测试通过分别计数。[原结果](../../../results/backbone-matrix-20261124.json) · [追加生成模型](../../../results/backbone-extension-20261124.json) · [问卷编辑器](../../../results/backbone-form-20261124.json)

**建库。** 13 个被拒的库已各获得一次公开格式或加载错误的修复机会。最终失败原因为非法控制标识或取值域 4 次，JSON 格式 3 次，浏览器加载 3 次，起始页面插入锚点 2 次，输出文件路径 1 次。DeepSeek Flash 的表格和问卷两轮均用满 16,000 个输出 token，响应标注 `length`，可见文本均为空。DeepSeek Pro 的问卷两轮都有可见文本，同样标注 `length`，两份 JSON 均被截断。Gemma 表格最后一次把选中的单元格预设为 10 个枚举值，超过 8 个选项的限制。Mistral 问卷的最小长度和星级数分别给了 11 和 10 个枚举值。Qwen3.5 的 SVG 设计使用了 `chartType`、`showAxes` 等驼峰命名。有限配置、用户操作后改变的运行时状态和控制名交付格式各需单独诊断。[原响应元数据与逐次原因](../../../results/self-failure-diagnosis-20261124.json)

**组装。** 有库可用的 160 个目标中，21 个未交付有效方案。其中 5 个返回空文本，16 个顶层字段与配置 schema 不符。Mistral 的 11 个表格无效回复均在顶层返回了提示中的 `public_project`、`requirements` 和 `schema` 等字段。逐题组装的提示可直接展示一个可提交的配置，以及允许返回的键。仍须严格校验原始响应并保留失败。[无效响应的顶层键及 SHA-256](../../../results/self-failure-diagnosis-20261124.json)

**行为。** 准入时检查了默认配置与首例能否加载；这一步没有验证拖拽、编辑或图表切换。GPT-OSS 的问卷在第 6 题能生成页面，但拖动排序后提交的次序错误，同一部署模型用参考组件和冻结 GPT-5 库均通过。DeepSeek Flash 的 SVG 第 2 题能加载，但缺少要求的折线图 SVG 节点；其从零生成、人工库和冻结 GPT-5 库三组均通过。Qwen-Coder 的问卷第 1 题交付了要求的模块文件，但指定的题目标题没有显示；该例冻结 GPT-5 库也失败。表格第 2 题中，Mistral 能用人工库和从零页面呈现菜单项，冻结 GPT-5 库交付的页面未呈现该菜单项，Self 在更早的配置交付阶段就失败。以上个例用于区分故障机制。[对应官方用例、页面与回执哈希](../../../results/self-failure-diagnosis-20261124.json)

**可归因范围。** 139 个有逐题页面的目标，固定首例回放与逐题配置逐项同过 12、同败 127。固定首例另过 3 项，原逐题方案均无效。两次 SVG 通过都出现在空白对照也通过的第 1 题。单靠实际交付的两个配置，不能判断其余合法配置是否也失败。限定同一模型、同一目标、双方均交付页面的 103 项，人工库与 Self 同过 10，人工库独过 90，Self 独过 1，同败 2。这个条件子集只用于检查交付后仍有多少差异。两种库的信息来源、接口和实现均有差别。另一个独立的表格研究保持当时的 GPT-5 接口和 Mistral 方案固定，四次重建均把通过数从 3/20 提至 16/20，为实现质量的作用提供了控制变量的证据。另一个基准 Duo 中，Qwen-Coder 自选与固定页各 1/10，实际通过的目标不同，因此这里的固定页结果只适用于上述三个 Web-Bench 项目。[逐项诊断](../../../results/self-failure-diagnosis-20261124.json) · [校准](../../../results/public-library-transfer-calibration-20261123.json) · [固定接口的重建](../../../results/compatible-library-rebuild-20261123.json) · [Duo 逐项配对](../../../results/backbone-overview-20261124.json)

## 复核

在仓库根目录运行下列命令。第一条只读取 Git 跟踪的公开 JSON，重算每个模型、项目、方法的故障位置和配对，不需要浏览器或 API。第二条还读取原始本地包、原响应、封存候选和指定的官方浏览器报告，重算响应长度、终止原因、控制标识和失败用例。只有具备全部原始记录的工作区可以复核第二部分。两条命令都不调用模型。

```bash
python -m studies.public_library_transfer.diagnostics.self_failures check
uv run python -m studies.public_library_transfer.diagnostics.self_failures check-local
```
