# 从筛选页返回时保留全部事项

已知修改视图函数后仍有两个原开发任务在浏览器后退时失败。检查模型自己的路由源码发现，Ministral 一份向正在遍历的事项数组追加元素，另一份把过滤后的可见事项写回状态。不给模型正式断言、报告或题号。固定已有两款模型、四份库、视图函数、每任务开关、从零组和另两种库。只向原模型提供公开路由接口、旧 route 函数和三个自拟序列。每份库只有在公开序列中未保留项目时才重写；最多两次，每次都需完全保留事项、顺序、编辑标记、下一个 ID，并且让 filter 跟随事件。原来已通过者保持原函数。训练时冻结输入列表以立即发现写入；控制器可以返回新状态或仅改变筛选标记。模型仍负责生成全部函数正文。

封存后在三个未用于生成的序列上复验，另对可运行的新处理器在真实浏览器中执行前进和后退，通过 hashchange 派发给同一绑定器。公开浏览器检查仅在过滤切换后比较事项列表及筛选状态。正式比较仍用原八个当前任务，两次建库均报告逐题与全开结果。论文用预定第一库，低分或回退同样报告。公开接口与原回执可复算。本阶段 $0.15 上限，计入同一轮 $20，截止 2026-11-28 10:32 UTC。运行 `uv run python -m studies.browser_worker studies.public_library_transfer.compact_todomvc.route_preservation.run`。
