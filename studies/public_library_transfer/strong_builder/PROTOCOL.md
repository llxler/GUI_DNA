# Web-Bench Table 的强建库模型诊断（2026-11-24）

本阶段研究在同一 Qwen3.5-9B 下，更换建库模型能否改善 GUI-DNA。预先指定 Table 的 20 个官方当前任务文件、两次独立订阅会话、每份库的逐任务配置与固定首例。不依据测试成绩选择库或重试。结果单列于开发诊断，不覆盖历史模型行。

1. 以 gpt-6-astra 在两个独立临时目录中建库。使用 11 月 24 日 Self 的同一公开建库提示、原始起始工程、资源和 20 条公开需求，沿用其字段归一化、格式与页面加载校验。每次只允许根据公开格式或加载错误修复一次。会话不得调用工具或获取测试、参考实现、人工库和原有成绩。保留会话事件和实际返回的用量；订阅用量不折算成 API 美元。
2. 两次均未获得模型响应时，改用 11 月 23 日登记的两套 gpt-6.2-astra Table 库，标明是档案复用且披露原始构建用量。只要任一新会话产出响应，就报告原定两行；建库失败计入结果，不以旧库替换。
3. 每份库分别交给 qwen/qwen3.5-9b，于每个任务按 11 月 24 日的 Self 配置提示作答一次，最多 8192 输出 token。并将建库时给出的第一份示例配置固定，原样评分 20 次。全部配置和页面冻结后才执行官方当前任务文件。比较现有同模型、同目标的 Direct、Self、Human 和 GPT-5 库，分别说明库和调用协议。相同任务上逐项配对，不合并独立库的分母。
4. 11 月 24 日 UTC 05:18 后不提交新请求。OpenRouter 新调用使用独立 2.50 美元预留上限；上一批次敞口 6.478155 美元，另项 Self 研究预留 4 美元，总额低于 20 美元。传输未确认的调用保留预留。格式或建库失败按未通过处理，缺失响应单列，不把缺失当作已测。复验运行 `uv run python -m studies.public_library_transfer.strong_builder.run score`；原始文件须保留在本地。
