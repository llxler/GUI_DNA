# 把资源属性和输入控件接到模型实际声明的接口

有的模块向组件 props 要资源标识，同一字段并非总从路由取得。另有模型实现了真实事件处理，却没有把公开的可访问名称接在相应的输入控件上。对原作者补建后尚未通过的单功能，先复用原件和同模型历史单功能源码，再按顺序检查这次补建时原作者已经交付的源文件；不得使用任何 Direct 输出。若模型模板的静态 URL 能唯一匹配公开请求，就从显式传入的业务属性或初始资源提供缺省值。定位控件时，仅在输入／动作的数量与公开操作一一对应时，按顺序绑定标签、占位符、测试 ID 或按钮文案。不改请求方法、响应判断、消息内容和官方测试。

对每份源码依次核验资源属性、控件绑定、两者并用，再组合先前已登记的通知／标签适配。按同一来源顺序采用第一个两例全过的替代实现。已经通过的组件保持原字节。全部来源（Self、GPT-5）规则相同。只见公开单功能操作中的 HTTP 地址、字段名称及用户动作，不从双功能用例调接口。沿用上阶段真实模型的全部选择；固定首对、按名选择、共用 Direct 和旧库同配置复算分别记录。保留前两行原五题，其余原十题。新增 API 费用为零。
