# 为组件挂载其声明的资源路由

单功能公开复验发现，模型向 /api/comments/${id} 发送 PUT 并正确更新状态，但父级只提供 MemoryRouter，没有匹配 Route，useParams() 拿不到 id。补建对象为上阶段仍未过单功能检查的组件。仅处理源码同时使用 useParams 和含具名插值的请求 URL、公开单功能请求能以同一静态前后缀唯一匹配参数的情形。只读公开请求的路径；不从返回体、用例名称、断言记录或双功能评分取值。

在宿主装配阶段增加真实 React Router 路由，将当前资源标识暴露给组件。优先使用实际父路由或调用方传入的对应属性，均缺时使用公开示例资源。候选来源、作者和顺序与前两阶段相同，分别检查原组件、缺省通知、字段名称修订与二者的组合加路由的公开单功能结果。只采用首个两例全过的组件。已通过组件保留原字节。先封存全部组件与模型选择，再运行同一批原双功能测试；不改请求或补发调用。另对采用路由的编辑页传入一个独立资源标识，核对同一处理函数是否访问新地址。新增 API 支出为零。
