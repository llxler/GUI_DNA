# 从单功能公开失败修复组件宿主

使用上一阶段已经冻结的单功能候选及选配。相同模型、域、来源、候选先后顺序。观察到两类可复现的接口问题。组件在自行完成请求后还会调用未提供的 onX 通知，使成功分支进入 catch；有些表单把同一编辑动词写在字段说明和按钮上。

宿主为缺省的 onX 通知提供空操作，保留模型自己的网络请求、成功及失败逻辑，显式传入的通知优先。对同组件已静态配对的 label／控件，去除字段标题末尾的冒号；若独立按钮上的动词恰为字段说明的首词，保留余下描述作可见字段标题，保留旧名为控件的 aria-label。普通标题、按钮、消息、URL、返回值和断言不变。依次验收原件、仅通知、仅标签、两者；已经独立通过的组件沿用。每种候选均必须在原公开单项上两例全过才能替代。若所有候选失败，保留上一阶段的原件。共享 GPT-5 库同样核对。每个目标仅重用原同模型冻结选择；固定与按名对照维持原规则。先封存全部候选再运行原十题和同一行原分母。新增 API 费用为零。
