# WebApp1K-Duo 单功能验收与双功能部署

这是十个既有开发组合上的新协议。固定主表六款生成模型、每行的原 Direct 和原目标（前两款博客五题，其余十题），保留全部组合。每个目标必须通过原文件的四个用例。先冻结来源、规则和单功能实现，再封存所有配置与页面，最后评分。公开单功能断言与组合断言重合，结论限于已知功能的重组。

- Human 来源审核覆盖基准固定版本的 Git 文件树、单功能与双功能数据卡以及作者发布的两个生成代码数据集。入组需能指认人工功能组件的实现作者、版本和文件。测试、生成器、通用 React 运行时和未记录作者的校准页面均保留其实际身份。
- Self 的候选均来自该行同一模型的既有单功能源码或此前只见公开单功能需求的域库。依准备时间顺序检查：首个域库按已冻结的功能映射，独立单组件、精简契约、套件重建、接收确认、状态钩子与视图、入参修复。每阶段 A 先于 B。每个功能采用第一份通过该功能两项公开检查的源码；无全过项则保留第一份可加载的实现并标出，缺文件则为空。禁止从十题 Direct 页面拆出组件。保留各阶段覆盖以披露额外准备资源。
- GPT-5 继续使用原登记的同域异组合捐赠模块，排除十个被测组合。按公开单功能对 React 的返回视图做隔离：枚举已交付源码中完整 JSX 子树，深度不超过五层；有多个可见子元素的容器按源码顺序递归。优先保留通过两项单功能检查且可见 JSX 节点最少的单个子树，同大小按源码顺序。不得合成功能、标签、端点或输出文本。没有通过的切片时沿用原模块。另测原始完整捐赠模块。
- 两种库均保留按公开双功能名组装及域内固定前两项两个控制，另用原目标模型的真实配置部署。若该模型缺少与新接口语义相同的配置，模型部署记缺测，确定性名称控制单列；不得把自动匹配当模型作答。固定对照按全部功能名称词典位置取前两项，缺模块时留空。
- 费用为本阶段新增零 API 调用，原研究的生成成本、外部 GPT-5 未披露成本及每个采用的库来源分别记录。单功能验收和组合正式评分分别用原 Jest 运行器。单独检查锁定版本 fetch-mock 的查询参数匹配行为，不改测试和分母。

离线配置优先取使用稳定功能名且已接收的首库 A 消息。同一模型、同一域采用一个预定来源，不逐题替换。Gemma 与 GPT-OSS 用原套件 A，Mistral 用原接收确认 A，Qwen3.5 用独立组件 A，Flash 用回调库 A 对应的实际编号和当时有源码的组件目录。Qwen3-Coder 只接受可映射到明确功能名的既有模型配置；无法建立对应关系时仅报告按名控制。配置中已选但库中缺失的功能不挂载，并保留缺失名。公开未通过组件仍参与评估；若域库无任何单项通过，记建库未过。事后的上游条件分析与研发结果分开。
