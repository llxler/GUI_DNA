# 可见控件目录与模型编写的按键状态转移

计算器初次分模块实验暴露了两个问题：小模型交付的复杂安装函数丢掉了数字操作，模型选择时又只见抽象组名，常在要求平方根时关闭科学键。本协议统一对 Gemma、Qwen3.5、GPT-OSS 和 Flash 执行，开发已见父阶段成绩。每个目标模型仍是自身所有新增业务代码的作者。用父阶段登记的可用首库或后续按公开检查准入的前后段库作为起点。四组与共同目标保持原样。研究者由公开需求提取了科学键、记忆键的可见标题并提供通用双寄存器绑定、错误处理和可选文本输出。每个按钮的显示更新、记忆更新、早晚档位次序、记忆面板标识均由该模型自己声明。原计算器核心、第三方服务或人工参考实现不会提供这些运算。外观和历史模块保持原模型源码。

同一目标模型为两组分别返回一个键目录和纯表达式。只验证可用的基本数值/字符串表达式及受限 Math 接口；不替模型补运算。缺项或语法错可纠正一次。科学、记忆独立接入。每次都用实际浏览器比较完整页，保留已过的公开检查、增加至少一项才接受。按预定顺序重建至多三次；没有提升则明示沿用有效原模块。另测把结果改成恒等变换的固定页，以及全关宿主。旧页、逐组判决、重建尝试保留。

部署时先实际打开每份库的完整页、各单组早期档或关闭档、全关页。逐模型保存实际可见按钮、显示值变化、当前主题和模式。模型只见这份公开目录与当题允许的需求前缀，一次选择候选编号。完整页是事先登记的默认；非编号可澄清一次，仍不合法就记失败。保持原方案部署新库、按新方案部署旧库、各自固定全开分别评估，如实报告下降和相同通过项。仅同任务且候选字节及官方环境完全一致时重用判决。四行主表统一采用这次有收据的最终流程，无价选优或按正式分数重建。新增上限 $1.65，计入并行阶段的完整上限后仍须低于全轮 $20，沿用 10:32 UTC 截止。运行 `uv run python -m studies.browser_worker studies.webbench.calculator.key_programs.run`。
