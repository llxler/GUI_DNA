# 表达式编辑器的一次 32k 准备窗口

2026-11-23，在完整需求阶段两次 GPT-5 建库响应均达到 16,000 token 且 JSON 截断后登记。此时尚未评分该阶段的正式候选。本跟进检验同一个最大准备 token 总量如何分配。原合同允许首轮 16,000 加一次 16,000 的公开修复（首轮合格即停）；本阶段库和无库笔记都只有一次最多 32,000 token 的完整输出，无准备修复。两种准备分别使用前一阶段相同的 GPT-5、全部 20 项需求、公共起始工程以及逐字相同的角色提示与独立新收据。所有准备产物先冻结，再分别给 Mistral 每项公开需求前缀与本组产物。沿用全 20 项、8192 逐目标上限、一次公共格式修复、相同评分器与原样官方当前文件。沿用同一运行合同下参考页及空白页的 20 项校准证据。不得复用有利的原目标响应。AI 文档第二个示例是固定页对照。只比较这两个具有新准备的流程。和原 16k 分段准备分开报告；不同采样、不同调用次数及不同实际费用使这无法成为严格的容量因果估计。未形成库或笔记时记录准备结局及未能部署的目标数，传输缺失独立呈现。费用由单独账本控制，须在其他阶段的真实敞口允许时才付费。
