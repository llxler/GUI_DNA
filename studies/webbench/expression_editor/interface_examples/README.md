# expression-editor 的方案格式示例

本研究在参考组最早的回答复制源码时单独登记。对原有 20 条首轮用户提示，仅在末尾重述冻结的闭合 schema 并给出一个空方案示例。模型始终看到同一参考源码、需求前缀和起始文件。干预同时改变接口说明的位置和示例内容，效果只能归于两项的组合。

与原研究逐目标比较首轮有效页面和当前文件通过数。另列同一冻结空方案及全开方案，并检查模型实际有多少次复制示例。[预登记协议](PROTOCOL.md)及[冻结、生成和验证入口](run.py)记录原始提示来源、独立账本与单目标测试边界。

### 观察结果

在原首轮与干预首轮均有模型响应的 9 个位置上，原提示产生 0/9 个有效页面，干预提示产生 9/9 个；当前官方文件通过从 0/9 到 9/9。相同 9 个目标上，固定空方案通过 4/9，固定全开方案通过 9/9。两种提示的可用首轮收据均记录为 DeepInfra 的同一 Mistral 型号，原始请求除消息外的生成设置一致。

| 干预条件全体 20 个预登记位置 | 通过的当前任务 |
|---|---:|
| 末尾附 schema 和空示例，每项独立规划 | 20/20 |
| 同一固定空方案页 | 7/20 |
| 同一固定全开页 | 20/20 |

新提示首轮获得 20 个响应，全部可编译，产生了 6 种不同页面。仅任务 1、2 采用提示中的空方案。全开页与按任务规划所得页在每个目标上的二元结果相同；这种比较支持说明方式改变了交付有效性，仍不能证明逐项选择胜过一次全开。20 次请求结清 0.020884 美元。完整数据见[逐任务来源与分母](../../../results/expression-editor-interface-examples-20261123.json)。
