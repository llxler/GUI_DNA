# expression-editor 空方案诊断

本诊断在知晓起始、空白、上游最终和参考库全开页校准后、正式三组逐任务候选评分前登记。问题是保留完整的发布模块、应用入口与基础编辑器，关闭所有公开可选项后，还有多少当前任务直接满足。所有 20 个官方文件均纳入，独立评分。诊断只涉及参考库。

- 方案固定为 `{"toolbar":[],"controllers":[]}`，不读任务来选参数。冻结页面保留六个生产模块、参考派生绑定和公共起始文件；加载时仍挂载具有字体、尺寸、边框的基础可编辑区域。解析、语法树、诊断和计算等模块在固定路径始终可被导入。空方案的通过具有上述多种可能来源。
- 控制器全开与同项目空白页、起始页直接索引已保存的同任务校准报告。新空方案只评分这一张冻结页。逐项辨认全开与空方案通过位置的差；这表示整套可选 UI 命令和控制器的联合作用，不能分别归因到某个挂钩。读公开需求可标注独立语言 API 与可见界面的不同目标，不重写官方测试。
- 共 20 个新浏览器作业，复用原三组合同和上游原始断言，每个作业是一个当前文件。新评分写入独立目录，正式候选、官方结果和模型输入互不写回。没有 API 费用。比较是独立固定页诊断，不计新的模型样本或基准覆盖。
