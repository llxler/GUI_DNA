# Web-Bench expression-editor 前瞻三流程协议（2026-11-23）

按公开生产模块与公开任务的可用性选择此前三种流程都未覆盖的 expression-editor。项目从内容编辑、工具栏扩展到词法与语法、静态诊断、执行、补全和历史。20 个位置全部登记。各位置只评当前官方 task-N 文件，截止时间与经费适用于本次独立账本。

## 三种流程各自获得的输入

| 流程 | 准备阶段 | 各任务部署时的额外输入与输出 |
|---|---|---|
| 参考组件＋GUI-DNA | 已发布的六份 ByteDance JS 生产模块、公开需求及参考入口 API 用法。编码代理改写选择性绑定并提供闭合接口。上游人时未知 | 完整冻结参考包，含六模块、绑定、编译器及方案说明。输出类型方案 |
| GPT-5 建库＋GUI-DNA | GPT-5 一次获得全部 20 项公开需求与起始文件。同时设计可复用实现、闭合接口和编译器 | 完整冻结 AI 包及文档示例。输出类型方案 |
| GPT-5 准备笔记＋无库生成 | 同一 GPT-5、相同顺序的全部公开需求与起始文件，准备可重复使用的设计笔记 | 冻结的文字笔记。Mistral 自由实现，返回新增或替换文件。笔记不会预置为代码 |

Mistral Small 3.2 24B Instruct 每次独立看到同一公开起始文件及截至当前目标的需求，再获得表中本组材料。准备过的强基线单列，不与从未准备的直接生成合并。两个 GPT-5 准备组均获可能透露未来需求的材料。任何模型均看不到其他组材料、官方断言、调试报告或此前候选。参考组所依赖的源码来自官方参考实现，具有不同于纯需求准备的先验。新绑定始终提供六个模块的路径；纯语言模块可能无需规划即满足相应文件测试。

## 生成、冻结与评分

- 在首次生成前公布准备协议、公开输入、模型设置、参考包以及全部 20 位置。两个 GPT-5 同一模型、medium reasoning、最多 16000 输出 token、温度/种子按已知模型约束省略；初次＋最多一次仅基于公开材料的修复，输出预算相同。建库静态检查与两个文档示例的通用加载检查中出现错误时，可获得实际公开反馈；笔记以 JSON 中的非空文字交付。笔记允许具体算法、接口、伪代码或代码片段，任何文字均不会自动执行为库文件。各准备阶段仅存一份首次合格的产物。
- 两份准备产物和每组 20 条逐任务提示必须先冻结，才开启 Mistral 推理。目标生成温度 0.6、种子 20261123（支持时）、每次最多 8192 输出 token、每目标每组一条首轮响应。三组同样只在返回的 JSON、方案编译或文件表无效时允许一次公开错误修复。行为测试失败不会产生新请求；API 传输中断不重新抽样，无有效响应记缺失。对同一位置列首轮和允许公开修复后的产物有效率、通过率与配对不一致数，未形成准备产物的整组如实列缺失。
- 预指定零推理控制为公共起始页、纯空白页、官方最终页、参考组件全部开关启用页和 AI 包的第二个文档方案。它们分别直接测试相同的 20 个单独文件。官方参考不通过或空白／起始页通过的位置继续纳入主结果，另报校准充分位置。固定页的成绩用于解释任务感知规划是否超出已有资产的默认能力。所有正式候选连同原始收据冻结后才能运行正式评分。
- Chromium、Desktop Chrome、上游生产超时（单用例 10 秒，断言 5 秒）、上游 Playwright 1.57.0、tinycolor2 1.6.0、单 worker，无重试，首个失败即确定当前文件二元失败。官方断言原字节保留。固定路径的项目测试如需定位候选，适配限于隔离的运行目录及文件服务，保留原始报告及哈希。三组协议完全共用同一套评分器。
