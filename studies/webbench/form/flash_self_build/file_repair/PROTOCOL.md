# 问卷全新库的文件定点修复确认

前一轮两份新库的公开 Node 诊断都定位到了启动文件中的非法 await，其中一份整包修复之后没有交付可解析 JSON。问题可以定位到文件，本阶段改变修复的单位。仅做 DeepSeek V4 Flash 问卷，最后一次独立双库确认；结果均保留。

- 各重复从空白目录调用模型，建库者只读原公开需求与起始工程。请求交付含源码的完整库，关闭建库额外推理，默认/首例和选项均由模型给出。接受原 JSON 或一个完整 JSON 代码围栏。沿用已登记的有限枚举收窄、静态模块入口接线。只在没有可接收源码包时允许一次完整包格式修复。记录全部回执。
- 对实际交付的每个模块作 Node 语法检查；用真实公开 form 入口加载默认和首例，保留源码位置、公开运行诊断和少量代表性公开交互观测。优先把具体的文件、行号、相邻源码和原公开需求交回同一 Flash，**只让它重写该文件**。其余字节、配置和首例冻结。位置不确定时由该模型指定其已交付文件并给出完整替换源码。最多三次定点请求；一旦可加载，最多额外尝试一次公开交互修复。首个无问题候选即停。已可加载时，只有公开待修项数严格下降且仍可加载才采用新补丁。更改记录注明源码、费用和保留原因。
- 不给模型旧库、参考实现、原/新官方测试或成绩。重新使用原任务前缀、原规划器设置和完整二十个当前文件；各自冻结第一次合格首例作对照。仅在两库、逐题方案与固定首例全部封存后评分。沿用原批 Flash 四组真实对照。若两个真实独立的新库在完整二十题均达至少十题，各自高于原 Self 和直接生成，并与此前库均有不同的实现，才判为预登记的重复确认。分别报告所有未达标情况。
- 使用第三份独立账本，上限 $1.50。额度情形按第一份账本全部封存，不确定金额照原保留，第二份如未完成按其整笔上限计，合计低于 $5。截止时间同本轮主协议。结构与交互诊断后才产生的代码一律标明是模型修复稿。
