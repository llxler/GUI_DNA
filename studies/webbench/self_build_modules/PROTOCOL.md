预定处理主表 A 的全部 17 个问题格：先问卷 Pro、问卷 Mistral、表格 Flash，然后其余表格、问卷、SVG（名册见 run.py）。每格两次独立重新建库，先登记 A 再登记 B；历史打分和参考实现均不进入模型调用。只读同批公开任务描述、起始文件、公开素材和本次模型的交付。项目的分文件和组间顺序取自公开需求中的模块名。模型自己提出布尔配置、默认值、首例、模块接口和全部实现。原起始 HTML 不改，模型写的 CSS 放入原编译器，JavaScript 由其自己编写的 index.js 挂载。仅建库阶段在支持的 DeepSeek/Qwen3.5 上关闭额外推理，GPT-OSS 保留原 low；两库分别用公开的原始 seed 和 seed+1（路由不支持 seed 时分请求采样）。逐题规划沿用原模型、输入前缀、解码与 8192 token 限额。

先交付精简的语义配置和模块接口，最多一次公开格式纠错。按源文件组请求原始多文件文本，同一库已交付源码随下一组传递，校验文件边界和 JS 语法，缺失或错误的单文件按具体诊断补交一次。默认和首例都须通过公开浏览器检查：表格右键须出现公开菜单，问卷须挂载问题并能改变原生选项，图表须在根节点挂载有图元的 SVG。加载错误或操作失败最多两次单文件修复；通过即冻结。固定页取冻结首例。对称性范围：这些公开反馈仅用于库准备，直接组复用原始真实响应；不能推断相同修复预算下的优势。

两库与所有预定逐题候选封存后，逐格离线运行未经更改的官方当前任务文件。A 区使用原主表的共同目标；两库也评估完整二十题，发布逐项结果、固定首例、建库及规划开销。只有在同批同目标的规划均已返回且第一份通过准备时才能替换主格；准备失败留空，已建成后返回的无效规划计失败，传输缺失不计失败。明确标示更换了建库协议；若第一份仍为零亦照报，公开列出两个重复。仅声称在两个独立库均高于原已建成的零分时重复恢复；原库未建成时只能声称恢复了交付/获得实际成绩。传输失败可按完全相同请求补传一次，均保留账本预留；鉴权、余额或路由拒绝关闭该模型。先完成双库的批次，达到时间或费用上限随即停止新调用。
