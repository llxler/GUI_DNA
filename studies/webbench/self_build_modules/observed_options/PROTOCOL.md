# 从已交付的单入口源码中公开可用配置

上一阶段在浏览器启动前拒绝了一些已有完整源码的包：例如存在七个实际选项，或声明了有读取和无读取的两类键。本阶段对全部 17 格统一应用以下规则，只针对某重复已明确未通过单入口准备的情况。其余部署原样保留。输入限定为该重复第一次单入口交付的同一份已结算源码；不看官方成绩，不尝试后续源码，也不调用模型改写实现。旧失败与本阶段费用均保留。

按 JavaScript 语法树找出 DNA_OPTIONS 对象内具有布尔字面量、且在原程序中通过属性语法读取的键，按声明顺序最多公开六个。其余选项保留生成者原值。装配器覆盖已声明的选项值，所有行为逻辑仍是模型自己的源码。若默认方案无法通过该项目的公开操作，按声明顺序每次翻转一个键，取首个通过者作为公开校准的默认和固定首例；每次从原默认出发。两个默认/首例页面均需通过与前阶段相同的公开操作。首个合格方案冻结后才让原模型按原前缀和参数产生新的二十份选择；不以固定页代替无效模型回复。

原 A/B 重复身份不变，只有准入失败才进入本阶段，每个重复最多用一个原始源文件。单独按真实范围报告恢复的库、校准值、逐题与固定对照，费用不重复计算。设 $1.30 独立账本。先验证已封存首批、套件的实际敞口，剩余活跃阶段按全部上限计，加上本阶段仍低于 $10。截止时间与本轮相同。
