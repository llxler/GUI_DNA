# Web-Bench flex 的响应式需求冲突

同一页能随屏宽改变布局。要判断换需求是否必须换页，比较双方时必须固定屏宽。本研究用第 12 至 14 步明确规定的卡片数，在同一数据、视口和页面状态上测试两份独立冻结的 GPT-5 medium 库。每个配置都经过原验证器、编译器和 Chromium。完整合同见 [PROTOCOL.md](PROTOCOL.md)，数字和输入哈希见 [结果 JSON](../../../results/flex-requirement-conflict-20261123.json)。

| 屏宽及任务对 | 两端要求 | 库 1 的完整方案空间 | 库 2 的完整方案空间 |
|---|---|---|---|
| 900 px，第 12 / 13 步 | 每行 3 张 / 2 张 | 8 个全部为 2 张 | 32 个全部为 2 张 |
| 550 px，第 13 / 14 步 | 每行 2 张 / 1 张 | 8 个全部为 1 张 | 32 个全部为 1 张 |

两份库均预先实现了较晚的响应式布局。对所测视口，即使知道每个配置的结果，重新选择也取不回较早的列数。两次全新页面加载观测一致。上游最终页面在两个屏宽分别为 2 和 1，固定的 1、2、3 列模板可由本判据区分。没有同协议 flex 人工库。

另检查既有匹配工作流的第 12、16 步页面。此处的配对目标是在同一个屏宽按时间顺序要求较早的 3 张和较晚的 2 张（900 px）或 1 张（550 px）。固定复用第 20 步页面，分别判早晚两端。第 13 步没有在该工作流保存，550 px 的这项回放和上表第 13/14 步的问题对应不同的早期要求。

| 流程及独立重复 | 900 px 第 12→16 步 / 固定第 20 步 | 550 px 第 12→16 步 / 固定第 20 步 |
|---|---|---|
| GUI-DNA，库 1 | 2→2 / 2 | 1→1 / 1 |
| GUI-DNA，库 2 | 2→2 / 2 | 1→1 / 1 |
| 无库，准备笔记 1 | 1→2 / 1 | 1→1 / 1 |
| 无库，准备笔记 2 | 3→行长不齐 / 行长不齐 | 3→1 / 1 |

从仓库根目录运行以下命令。第一条按输入哈希及原始矩形复算报告，第二条在独立临时目录重新执行全部浏览器检查。完整实验环境需要原项目的只读产物目录，运行不调用模型。

```bash
uv run python -m studies.flex_requirement_conflict.run check
uv run python -m studies.flex_requirement_conflict.run replay
```

原始矩形、两次校准与冻结清单存放在 `artifacts/flex-requirement-conflict-20261123/`。结果只衡量公开要求中的卡片列数，原官方文件与通过计数保持独立。
