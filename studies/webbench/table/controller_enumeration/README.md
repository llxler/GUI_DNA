# Web-Bench table 的全部控制器配置

table 的参考组件包有六个可独立启用的控制器。冻结编译器以固定顺序挂载，无论计划数组内按何种顺序列举，均落在 64 个可区分的页面之一。本研究在原三组结果公布于本地后事先登记穷举全部配置，用于判断在该来源下随机选择控制器能完成多少当期需求。

每个配置面对二十个独立的当前官方文件。逐目标的 `passing / 64` 是对六个开关各自以二分之一概率启用的精确通过概率。对二十个目标分别随机配置的预期通过数是各目标通过概率之和。每个文件在每个页面上只观测一轮浏览器运行。原论文流程采用每目标独立模型选择；固定全开页和均匀开关配置均无需模型推理。

### 全部 1,280 个位置的结果

64 个配置、20 个目标的矩阵有 592 项通过。均匀配置的通过比例为 46.25%，二十个目标的预期通过数为 9.25。逐目标模型规划通过 20/20，预先指定的固定全开页也通过 20/20。

| 每个目标能通过的配置 | 目标数 | 官方任务编号 |
|---|---:|---|
| 64/64 | 2 | 4、11 |
| 32/64 | 11 | 1、2、3、5、6、9、10、12、13、19、20 |
| 16/64 | 7 | 7、8、14、15、16、17、18 |

例如，点击以选中单元格和点击/双击进入编辑由常驻核心实现承担。其余 18 个目标的结果随控制器配置发生变化。在固定另外五位、只把一个控制器从关闭改为启用的 3,840 对观测中，576 对从失败转为通过，0 对从通过转为失败。因此，这个组件库内选哪些行为会影响运行结果，而不加区分地全部启用已经覆盖了这批任务。

已有 35 个位置可按同一任务、相同评分合同及全部页面文件的逐项 SHA-256 完全匹配，复用其原报告；剩余 1,245 个位置独立运行。详见[预登记协议](PROTOCOL.md)。
