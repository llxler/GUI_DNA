# 同一选区接口下的 Table editor 自建库

七个主表模型都从公开起始工程和 20 条公开需求重新建库，各自逐题配置。研究者提供模块边界、浏览器事件的归属和共享状态字段。所有 DOM 变更、选区计算、菜单命令与样式均由该行模型编写。生成器只见公开材料、自己的实现及开发探针的操作观察。此前已在该项目调试，因此结果是开发题上的复测。

先生成选区与菜单两个模块，要求首份页面同时能打开菜单、实际插入行、在表外关闭、单击选格，并且浏览器无异常。各模块仅用实际存在的 DOM 和已定义接口。未通过的核心最多按同一模型的公开错误修复两轮；仍失败可重新从零建一次。接受第一份达标的核心。然后逐个增加键盘、鼠标、剪贴板、尺寸与拖动模块。一项扩展只能在保留全部已通过公开动作且不引入异常的前提下保留。语法失败或破坏已有动作可修复一次。完整记录拒收与修订。原官方测试、参考实现、其他模型的代码均不用于生成。

目标模型在自己库的累积配置间逐题选择，输入是截至本题的需求、可安装的模块及公开观察。另测固定全开和空宿主。封存候选文件与配置后，才逐个跑原始当前任务的官方断言。各模型使用同一组 20 个目标，保留原 Direct、Human、GPT-5 对照。新协议完整交付时采用全部对应结果（含实测零、退步、建库失败）；传输缺失另记，无分数冒充零。固定全开仅作对照，不依据正式成绩挑构建或配置。
