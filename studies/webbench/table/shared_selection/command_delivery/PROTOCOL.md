# 原作者的短回调与事件参数接收

这是同一开发项目上的公开交互修复。触发规则在事件路由阶段的全部库交付前登记，不读取前两阶段官方评分。七款模型均按同一规则检查。前两阶段保留各自的候选、费用与正式结果。触发条件只有建库失败、或原全开页在公开键盘流程上尚有缺项。

1. 原失败库的作者有时在最短的插行函数内复写整套编辑器，输出截断。保留作者有效的菜单声明，给每项命令只发该动作和真实参数。先交付插入行与选格核心。可选动作语法错误时记录并保留其他已交付动作。菜单外壳、只用外壳的对照与原公开准入完全沿用。若原选区实现导致异常，同模型分别写选择投影、矩形范围、编辑状态及单击处理，研究者仅初始化字段、传入实际事件及元素。随后测固定页面和空宿主。
2. 键盘回调里出现未绑定的 event 别名 e。先重收同模型已有短函数，按原次序将同一 DOM 事件同时绑定到两个名字，再在首个保留既有公开通过项、增加覆盖且无异常的页面停止。若仍有缺项，原作者按移动、选择和编辑分组补交短函数。各组只提供签名和该组公开要求。按组保留有效实现；已有有效全库不能因一组交付异常失去准入。绝不使用另一模型的实现。
3. 新准入库依次追加鼠标、剪贴板、布局和行列拖动；每次接回都保留已通过操作。所有修改以固定全开页的公开动作判定。原库与源码完全相同的模型沿用上一阶段的实际选择；源码改变的模型重新从自己的累积配置逐题选择。正式评分在封存后一次运行，用全部结果更新这一列。同题 Direct、人工库与 GPT-5 库沿用原记录。已测零、建库失败和传输缺失分别呈现。
