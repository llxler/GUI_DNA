# Web-Bench table 共享状态契约实验

此前 GPT-5 建库、Mistral Small 3.2 逐目标规划，在相同的 20 个当前任务文件上首轮通过 3 项。本实验从公开的需求和起始工程重新建库。GPT-5 设计共享状态与组件职责，Mistral 编写组件，再按每个目标的公开需求前缀选择组件。两次独立建库只共用流程和公开输入。流程涉及不同的建库信息、模型分工与编译器；比较单位为整套工作流。[预先固定的方法和确认条件](PROTOCOL.md)

## 离线复核

从仓库根目录执行。需要本轮本地封存产物、独立账本、冻结的历史对照与 Web-Bench 快照。

```bash
uv run python -m studies.contract_library.evaluate check
```

`check` 只读复算，验证生成输入和存档哈希、两套独立请求与账本、每次设计/公开修复的消息与真实响应，并从当前任务的官方报告重算可判定结果。首次评分使用 `score` 子命令，要求已存在 `generation-complete.json`。对可部署的库，闭合模式与编译器重建每个首轮方案，以及全关和全开两个固定方案的完整文件束。只有任务 ID 与完整文件束的哈希同时相同时，才共享同一份官方报告。没有可评分页面时不启动浏览器。三个历史对照固定取自[原研究首轮结果](../results/table-library-sources-20261123.json)。

准备失败、规划未收到响应、收到无效响应和可执行方案分别计数。收到无效方案计首轮失败；准备失败或传输无响应的目标不进入共同可判定分母。只有两次独立建库各自都在同一组 20 个目标上收到首轮响应，且各自通过超过 3 项，才达到本研究的确认条件。
