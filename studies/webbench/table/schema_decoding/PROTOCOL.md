# 表格规划的模式约束解码

在看到两个公开自建接口各产生 0/20、19/20 个合法自由输出、原 GPT-5 库为 14/20 后登记。旧的自由解码结论与门槛封存，本研究用同一三套库检验语法约束下的整个流程。原有三套模型输入逐字沿用，各任务只看此前缀、starter、各库自己的接口和示例。Qwen2.5-0.5B-Instruct 同一权重，单样本贪心。解码器只从库自身的闭合 JSON 模式得到语法，不读取原方案或任何测试。固定按模式属性声明顺序填写全部属性，包括可选项。括号、键与分隔符由程序写入；对于每个布尔或枚举字段，仅保留合法候选值的 token 前缀，在每个真正分支上由同一语言模型当前的 logits 贪心选择下一 token。保留分支候选、logits、选择及最后的完整配置。三套库均只需对象、枚举与布尔值。算法尚未覆盖无界数值与数组。语法强制不意味着会规划正确。

旧 GPT-5 库和刚才冻结的两套全公开 Codex 库分别运行全部 20 个目标，事先固定三份接口和真实提示。严格部署新生成的方案；与各自同模型的自由解码首轮及预指定首例对照，另列旧 Mistral 历史 3/20。仅以完整且合法的全部 20 个新回答做确认：两个新库须各自超过历史 3 项与同时期原库受约束的通过数，并各至少持平自身自由解码严格通过数，且至少一个重复严格增加。达到则将“公开需求自主建库＋闭合方案约束解码”加入旧 AI 库逐协议重测清单。只验证了表格这 20 项，不以已知分数筛候选或重试，不改变此前研究的阴性条件。另报告固定首例、不同方案数量和是否有任务选择独占收益。两次自主建库并未在得到约束解码反馈后修改。代码、输入先封存，全部 60 个输出封存后才评分；06:12 UTC 后不启动新推理。
