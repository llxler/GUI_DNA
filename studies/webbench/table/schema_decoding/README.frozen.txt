# Web-Bench table：约束解码选择布尔与枚举配置

旧 GPT-5 库和两次完全公开重建的库各自重新接收 20 个真实方案。Qwen2.5-0.5B-Instruct 使用与各库上次自由解码逐字相同的模型输入。解码器按模式声明顺序写出键和 JSON 结构，包含所有可选字段。模型在每个布尔或枚举值的合法 token 分支中按 logits 选择。三个库的输出合同、固定页对照、准入规则和实验设计时间见[登记协议](PROTOCOL.md)。

| 表格库 | 同期自由解码严格通过 | 同期自由解码并允许回退首例 | 约束解码严格通过 | 总是使用首例 |
|---|---:|---:|---:|---:|
| 原 GPT-5 库 | 2/20 | 3/20 | 3/20 | 3/20 |
| 公开重建一 | 0/20 | 18/20 | 18/20 | 18/20 |
| 公开重建二 | 17/20 | 18/20 | 18/20 | 18/20 |

三套库各自收到 20 份合法的约束解码方案。两个新库都多通过了原库未通过的 15 个目标，没有丢失原库通过的目标，达到本轮登记的复测条件。两组新库也都在全部 20 个目标上生成了与各自全开首例逐字节相同的页面。因此在 table 上，选用固定首例就能复现两组的全部通过项。两项仍失败的目标为 8 和 9。80 个不同的任务与页面组合中，70 份报告按完整文件哈希和任务复用，10 份新执行。初次本地 GPU 会话因显存争用中断，没有生成完整响应；同输入和模型恢复后的全部 60 个逐题输出均保留。[结果与逐任务配对](../results/schema-constrained-table-20261123.json)

复验需有本轮封存产物、此前的官方评分和已登记的本地 Qwen 分词器。命令核对完整输入、响应与官方报告的哈希。构建候选时会逐行重放所有值的合法分支和最大 logit 决定，重新拼出原生成 token。候选全部封存后，只有相同任务、相同完整页面的历史官方报告能被复用。

```bash
uv run python -m studies.schema_constrained_table.evaluate check
```

初次离线复验依次运行同一模块的 `freeze`、`score` 和 `report`。每个目标只执行当前任务文件。相同 20 个任务在两套新库上的结果分别列出，表内不累计成 40 项。
