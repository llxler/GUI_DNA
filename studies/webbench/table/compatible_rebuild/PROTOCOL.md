# 表格库的独立兼容重建

2026-11-23。已知旧成绩后设计的配对研究。使用原 GPT-5 表格库的公开计划 schema、说明和两个示例，向四个独立的 ChatGPT Codex 会话提供相同的完整公开需求、原始起始文件、部署接口。普通提示和契约提示各生成两次，模型与推理设置相同。普通提示要求实现需求并提供可配置的模块。契约提示另外要求从起始 DOM 和可观察的状态转换推导模块所有权、事件优先级和边界行为。均由同一个确定性编译器保留原始 HTML 与 CSS，再加载各自生成的 CSS 和 JS。两组都可利用公开需求中的模块名。工具禁用或按事件记录检查；若发生外部工具调用、模型输出或包验证失败，该重复登记失败。每组仅取首次输出，无分数反馈、修复或择优。构建在独立临时目录运行，不提供旧库的源码、历史答卷、参考实现、隐藏断言或任何成绩，记录模型、请求与输出哈希、用量。使用现有 ChatGPT 订阅，推理量与 OpenRouter 账本分别披露。

在四次构建均结束并封存后，重放两批原始 Mistral 的首轮计划，各 20 项，所有方法共用同一响应和原始协议的有效性规则。报告旧后端、两次普通新后端、两次契约新后端的当前任务分数，以及各库部署第一份固定示例的独立 20 项控制。按目标登记 gains/losses。按协议准备失败不计为已观察的 0/20。将推广性验证设为：同一重复的契约实现必须在第一批同时超过旧后端和普通实现，两次均满足；第二批两次契约后端均至少持平旧后端且各有新增通过目标。达到才在待办加入所有历史 AI 建库的重新测试。只在超过旧 GPT-5 时也如实报告，但它同时改变了建库模型和实现，不能推出契约提示的优势。原规划器曾看到旧库源码；这项实验隔离了同接口下后端实现的影响，不能替代新库独立端到端规划。两个重复使用相同 20 个任务，单列结果。
