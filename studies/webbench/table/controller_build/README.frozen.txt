# Web-Bench table：从公开起始工程独立设计行为接口

两次独立建库均只向 GPT-6.2 Astra 提供公开需求和起始工程。每次建库自行选择可切换行为、名称、默认值和第一份配置。两套库各自生成了六个布尔开关，并都在首例中启用了全部六项。Qwen2.5-0.5B-Instruct 针对每个库与每步需求独立生成首轮配置。[预先登记的输入、收费方式和确认条件](PROTOCOL.md)

| 库 | 收到首轮 | 合法首轮 | 严格通过 | 无效响应回退首例后通过 | 总是使用首例 |
|---|---:|---:|---:|---:|---:|
| 原 GPT-5 库，当次 Qwen 对照 | 20/20 | 14/20 | 2/20 | 3/20 | 3/20 |
| 独立新库一 | 20/20 | 0/20 | 0/20 | 18/20 | 18/20 |
| 独立新库二 | 20/20 | 19/20 | 17/20 | 18/20 | 18/20 |

第一套接口收到十份多了一层 `configuration` 的响应、六份语法错误的 JSON，另外四份含模式等额外字段。第二套接口的十九份合法响应都与其首例相同。逐项核对可见两套库回退后的通过目标集合都分别等于固定首例；两套库的首例都在任务 8 和 9 失败。严格首轮改善只在第二次重现，未达到两次都改善的预设条件。[逐任务配对和原始哈希](../results/public-controller-table-20261123.json) · [原库独立对照](../results/table-local-original-recovery-20261123.json)

持有原始产物时，从仓库根目录运行 `uv run python -m studies.public_controller_build.evaluate check` 可以只读核对两次构建、40 份独立规划回应与 40 份不同的当前任务官方报告。初次离线评分依次运行同一模块的 `freeze`、`score`、`report`。重复任务与相同完整页面共用报告；研究只评估该步需求的任务文件。
