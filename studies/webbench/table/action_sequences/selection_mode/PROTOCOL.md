# 区分选中与编辑的同模型修库

两份不同种子的 Qwen3.5 表格库都在单击时直接进入编辑，Enter 随即退出，Escape 清空选区。两库的单击和编辑键函数逐字相同。从上一阶段封存的两库出发，请同一建库者修复四个相互调用的函数。模型只看自己对应的函数、事件接口、公开需求及训练中的状态约束。按普通单击、编辑键、选择集合、移动这四个职责分别改写。每个函数请求一次，语法无法接收保留原函数。修复额度 $0.16，纳入表格与网站生成共享的 $1.60，截止 12:48 UTC。

先用原有公开动作、原训练序列、普通点击后的编辑状态和编辑退出后的选择验收。按固定次序检查四个替换的组合，以及单独的点击、点击与编辑键、选择集合与移动、仅移动。采用首个保留全部原通过项且新增至少一项通过的版本，保留所有试过的结果；如果均不满足条件沿用原库。候选准入后才进行正式评分。逐题沿用原配置，重编原函数必须得到原页面哈希，再用完全相同的配置编译修订函数。每库同题复验 20 题，另列固定全开、空宿主和原 Direct。此设计衡量同一配置下换函数的效果，单独报告，不移动正式主表的格子。

此前已经查看上一批三段诊断，其中一部分现用于解释开发问题。额外冻结两段从未用于修复的顺序，封存后在公开参考、起始页、原库和新库固定页执行。一是两个单元格先后编辑并退出，二是从内部单元格开始的四方向闭环。各步检查实际选中单元格及可编辑状态。只解释参考能完成且起始页不能完成的序列。保留同分、下降、不可运行和全部回执。
