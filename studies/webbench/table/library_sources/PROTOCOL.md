# Web-Bench table 三流程配对研究（2026-11-23）

在既有 AI 库上新增第一个 table 参考组件组，按上游可复用模块的结构选项目。table 是此前 AI 库研究中的项目；此前三组同协议项目为 dom1、form、svg-chart。比较进入每一项公开需求时交付的当前页面，公开主表保留每个生成模型和建库者的分层。

- 三组按共同位置 task-1 至 task-20 各生成一次。模型均为 Mistral Small 3.2 24B Instruct，温度 0.6，支持时种子 20261123，最多 8192 个输出 token。每次独立从无状态上下文开始，获得公开的初始 HTML/CSS/JS 和截至该任务的需求。三组都继承相同起始文件。参考组和 GPT-5 库组另获各自完整冻结包并输出闭合类型的 JSON 方案。直接组仅获公共输入，可自由新增或替换文件，以 JSON 文件表交付。每组均禁止在方案中传入测试、反馈或历史页。
- 参考组沿用 ByteDance 发布的七份生产模块、最终 CSS 和起始 HTML/JS。编码代理查看公开需求、模块导出与上游参考入口，并按其注册顺序新写六项独立可选控制器的类型方案及绑定代码。核心 Table 始终实例化，各控制器内部已经实现多项行为。库的最终参考资产包含后续任务信息，规划器可以多开功能。入库清单显式排除 util.spec.js。参考实现的原开发人时未知；记录本轮代理从查阅资料到冻结的实际墙钟跨度，含准备研究协议和运行器，不能解释为人时或上游开发成本。
- AI 组沿用先前从 table 全部公开需求构建并冻结的 GPT-5 包。建库者未获参考代码和官方测试，历史建库费用与本轮规划开销单列。直接生成只能看到需求前缀。研究比较带这些先验资产的完整流程，无法分离建库信息优势、行为实现质量和方案选择的因果作用。
- 预登记主要终点为第一次有效送达模型响应的当前官方任务文件全通过。收到响应但 JSON、文件或闭合方案无效计失败；未获得可用供应商响应记缺失。另给三组同一机会：仅对格式、文件表或编译无效的已返回响应，以相同模板提供实际公开错误一次。返回合法页面即停止，不对隐藏行为错误重试。每组按首次、一次公开修复后分别列出有效产物数及当前任务通过数。未收到修复响应记该修复策略结果缺失；公布共用分母，不用缺失预留推断零费用。
- 固定页面控制在请求前指定。起始页和上游最终页校准评分环境；参考包启用所有六个控制器及 AI 包第二个文档示例各编译一次，用同一页独立评分 20 个当前文件。这些静态对照检验逐任务规划在本项目带来的增益。全开页仍只跑当前任务文件。最终页校准不通过的位置保留在主分析，并另报校准充分位置。各组测试与对照生成分开；任何官方结果都不能进入提示。所有请求及页面冻结后才运行候选评分。
- 仅运行上游未改动的 task-N.spec.js，Chromium、固定 Playwright 1.57、单任务单 worker、首个断言失败后停止，报告任务级二元分数。所有计划位置进入完成度报告。对共同已观察位置列三组计数、配对的不一致方向；单模型单项目仅作描述。比较冻结输入与编译有效性，再看运行时行为通过，借鉴 LaTCoder 对中间表示和下游产物的分开检验。
