# 让目标模型划分自己的表格库

Mistral Small 3.2、Qwen3-Coder-30B、GPT-OSS-120B 在原主表的 Self 分别低于、等于、等于 Direct。本阶段各自只看完整公开需求、起始页和最小模块接口，自己决定二至五个模块的文件名、顺序、所覆盖的公开需求和共享函数接口。研究者只提供按顺序安装所选模块的入口，传入原始表格、共享状态与自定义 API 空对象。不会提供菜单、选区、键盘、拖放或编辑的实现。逐模块生成只见公开需求及自己写的设计和之前模块的接口。布尔配置通过启用依赖顺序里的前若干个模块确定。

先生成设计与实现。浏览器按公开操作检查菜单、插行、表外关闭、选区、箭头、Tab/反向 Tab、编辑和删除。允许两轮由原模型根据实际观察修复模块，一次修一个文件，保持已有通过项并增加通过项才保留。服务未交付另记。库要通过菜单打开、插行、关闭以及单击选区四项，且无实现的宿主无法完成这些操作。失败则重新生成设计和全部实现，最多三份独立新库，严格取第一份准入库。建库过程中不使用官方测试或得分。另用不同起点的连续浏览器操作检查已封存的实现。

每个目标模型对全部二十项独立选择一次启用的模块数。另评分固定全开和全部关闭，使用同一项目、目标、环境的官方当前测试。新库准入且在行内此前全部共同目标有观察时，主表报告该新协议所有涨跌。建库失败的格留空，无法交付标缺测。本次源码、第一库和重建均与原主表记录分开，保留以前有效成绩。新增上限 $2.25，当前各已封存阶段按实际账本敞口计算，仍在建库的计算器阶段按其完整 $2.50 预留。沿用 $20、10:32 UTC 的总授权。运行 `uv run python -m studies.browser_worker studies.webbench.table.model_modules.run`。
