# 用实际 DOM 接口修订短处理函数

四处理函数实验中，Mistral 实际创建了菜单，却在插行时调用未实现的 env.api.insertRowAbove。Qwen 能在表格中插入真实行，关闭它自己新建的菜单时却调用早期库的 hideContextMenu。模型自报的模块接口包括计划实现但没有正确接通的函数。此处只对上一阶段最后仍未准入的模型进行操作，不改变已成功的库。每份设计复用同一作者上一阶段的四个初始处理函数并核对其封存摘要。默认保留能通过公开动作的函数，按同一失败检查修订相应函数。模型只看真实参数、它的原函数与同组短函数、公开需求和浏览器结果。明确限制为标准 DOM 和自己已有的共享状态，接收时拒绝调用任何应用级 API。真实菜单节点、表格和单元格直接作为参数。仍由模型自己决定增删行列、关闭、渲染与选格行为。

最多重建两份原设计，严格按照原顺序与相同准入、本模型同一目标选择、原实现、固定页和空宿主计分。接收器不会补写业务代码。上一阶段无可复用的首答时，原作者在相同的 DOM 接口内生成短函数。新阶段上限 $0.65，计入其他所有并行上限最高不超过 $20，沿用 10:32 UTC 截止。本实验已见先前项目结果，是针对公开接口错误的开发复验。运行 `uv run python -m studies.browser_worker studies.webbench.table.event_hooks.dom_contract.run`。
