# 表格项目的公开起始工程绑定干预

2026-11-23，在已知旧库 3/20、人工组 20/20，且看到旧 GPT-5 编译器重写的表格初始单元格编号与公开起始工程不同时登记。此次不新发模型调用。问题是在 GPT-5 已交付的同一行为库和 Mistral 已交付的同一批方案上，让 AI 库沿用公开起始页面能否提高官方当前文件通过数。干预属于建库后的确定性装配，不是新的 GPT-5 抽样或独立的盲建库复验。

1. 原包取冻结的 GPT-5 table 包。新包只改编译器：对同一 plan 调原编译器得到各文件，使用公开起始 index.html 作为初始 DOM，移除原起始 script 标签后，在文档末尾按生成页原顺序插入所有生成 script（包括配置和模块）。保留起始页面的外链 CSS，在生成 index.css 后追加公开起始 index.css。该项目两种 HTML 都使用同一 index.css；不处理含其他样式资源的包，不承诺此策略适用于其他技术栈。新旧行为模块、方案模式、文档与示例相同。新编译器只含旧编译器和公开起始 HTML/CSS。未读取官方断言来制定该规则，未用本实验行为反馈修改包或计划。它同时改变 DOM 与重叠样式，不能分离这两种改动的贡献。
2. 主批次包含 11 月 23 日 table 三流程实验中 Mistral Small 3.2 全部 20 个 AI 库首轮原始回答，沿用当时的累计公开需求和 8192 逐目标上限。确认批次取较早 webbench-expand-run 中同一 GPT-5 库和同一 Mistral 的 20 个独立首轮原始回答。旧批次使用独立的原始提示、日期与上限；在每一个批次内部比较同一条响应的原装配与新装配。原始无效输出在两侧仍记无效，传输缺失记未知，保留独立分母；两批不合并。另将每包第二个文档示例固定编译一次，分别对 20 个当前文件评分。独立计划回答来自同一个旧库，不代表独立重新建库。
3. 固定完整输入、所有新旧页面并封存后才同时评分。沿用此前 Chromium、Playwright 1.57、每次一个原样官方当前文件、单 worker 的合同。仅对同一当前文件且全文件哈希相同的页面复用结果。报告各批次首轮收到数、可编译数、通过数、本来通过但退步/从失败转通过/双过/双失败的目标清单。若主批次和确认批次均有 20 个共同收到的位置且各自主指标严格上升，可以确认这两批冻结方案上的装配改进。达到该标准不代表新建库模型、其他项目或跨项目的改善。此次结果不覆盖旧报告。

同期无库对照在各自一批内独立呈现。11 月 23 日的原始无库首轮继承公开起始文件；更早的 webbench-expand-run 无库首轮按其原有合同从空目录生成全部文件。沿用各自原始首轮输出，从相同的 20 个当前文件重评。该对照不参与判断装配改动的配对收益。
