# 从零生成文件包的离线接收复验

文件管理器的 Direct 提示要求返回 JSON 文件包。此前完整 HTML 检查器只检查回复内是否出现 HTML 标记，可能把 JSON 包装和转义字符一起交给浏览器。保留每个原始判决。本次对主表文件管理器的 Gemma、Qwen3.5、GPT-OSS、Flash 全部二十个原始回复统一检查，用交付收据验证原文。去除外层围栏后，以 JSON 对象开头的回复必须按完整 JSON 文件包解码，再由原文件路径和内容规则验证；不会从不完整 JSON 中摘取内嵌 HTML。独立完整 HTML 使用原 HTML 准入。继承原始起始目录，生成器的文件内容逐字保留。合法空白页、不可编译回复、缺失交付分别按原规则处理。研究者已见部分初算结果；这次是接收器纠错，不是新模型实验。官方判决、库源码、随机种子均不变化。

登记所有原始回复、源码与官方环境后，一次封存全部页面，再评价所有任务。与同题同环境旧页字节相同的可以复用其已校验报告。论文对四行一律采用纠正后的 Direct；涨跌和无变化都照报。三种库方法沿用同一行的原资料。计算器另用整页 HTML 提示，在接收审计中检查其四模型页面，但不与文件包混评。本阶段没有 API 客户端调用，费用为零。

运行 `uv run python -m studies.browser_worker studies.webbench.file_explorer.target_models.direct_reception.run`。
