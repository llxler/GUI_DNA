# Web-Bench SVG 图表的兼容后端重建

两次独立的 Codex 建库会话分别实现同一套 SVG 图表接口。每次接收公开的 20 项需求、起始文件、静态资源，以及此前 GPT-5 库公布的文字模式和两个示例。保留原接口，使同一组 Qwen 首轮计划可以分别在新旧三个后端执行。[预登记协议](PROTOCOL.md)

本地复验时，`uv run python -m studies.compatible_chart_rebuild.evaluate check` 核对原始订阅响应、Qwen 逐题回答、输入与页面哈希、浏览器回执和最终汇总。`fixed` 和 `strict` 两个子命令分别执行各新库第一示例与有效规划页的官方当前文件检查。加载失败、非法计划、缺失响应和固定示例回退均保留原有标记。相同目标上的回退和固定页共用同一份官方回执。

另行登记的敏感性只接受恰好包裹整个回答的一对 JSON 代码围栏，去壳后仍须通过同一数据类型检查。`uv run python -m studies.compatible_chart_rebuild.fences check` 复核此项。该规则登记时已经见到首条 Qwen 输出的格式。[单围栏协议](FENCES.md)

## 结果

下表每格的分母均为同一项目的 20 个官方当前文件。两份独立新库采用同一契约提示，各通过两份文档示例的公开加载。Qwen 裸 JSON 有效数为 0/20，因此主研究中的回退部署在每个目标都使用首例。

| 部署方式 | 原 GPT-5 库 | 新库第一次 | 新库第二次 |
| --- | ---: | ---: | ---: |
| Qwen 严格 JSON 首轮 | 0/20 | 0/20 | 0/20 |
| Qwen 严格失败后用各库首例 | 17/20 | 18/20 | 18/20 |
| 固定各库首例的独立对照 | 17/20 | 18/20 | 18/20 |
| 额外接受单层围栏 | 8/20 | 8/20 | 8/20 |
| 额外接受单层围栏，其余回退首例 | 16/20 | 17/20 | 17/20 |

两次新建的固定页都新增通过公开任务 14 的阶梯折线几何，原有通过项均保留。单围栏规则恢复了同一批中的 10 个合法回答；每库的这 10 个回答分别编译成一个相同页面，三个后端均通过其中 8 个当前文件。其余 10 个位置改用各库首例后，两份新库才各多通过一次。严格规划未达到预先登记的跨重复提升条件。[逐题配对和订阅用量](../results/compatible-chart-rebuild-20261123.json) · [围栏敏感性与逐题回执](../results/compatible-chart-rebuild-fences-20261123.json)
