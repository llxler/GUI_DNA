# canvas 输出容量跟进

在 16,000-token 阶段两套库共四份响应均触顶并无法解析后制定，决定依据仅为公开生成阶段的记录。两次重复各自重新生成全部内容，包括直接生成的准备笔记及目标。沿用 matched_canvas 的项目、需求、运行合同、五个目标、GPT-5 medium、独立准备、一次修复以及当前官方文件评分。两组所有请求的输出上限同时设为 32,000 tokens。该上限包含推理。首批和跟进各自完整报告。

每组每重复的费用上限取 $4 与四组均分当日剩余授权金额的较小者，向下取整到美分，并受当时实际可用余额限制。首批全部账本的结算及未决预留都计入已用授权，旧账本先关闭。时限继承首批。复用相同原始校准报告、静态资源和浏览器运行器，保存独立的协议、运行哈希、生成及评分清单。计费纳入准备失败和修复。两个阶段是独立请求，不能将差异归因于 token 上限这一项。固定页与公开按键诊断沿用已固定的规则，在本批已生成的库上执行。
