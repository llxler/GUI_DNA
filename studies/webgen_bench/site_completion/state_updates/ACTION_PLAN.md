# 明确区分提交反馈与状态变更

首轮可选状态扩展在三个预定站点全部返回空对象，启用与禁用更新的 HTML 在每站逐字节相同。保留这三份结果。另行登记一次配置方法修订，仍使用 Flash、同三站、同 SDK、同原页面。另加原先诊断的游戏页，仅作已见案例，独立报告。配置阶段只读公开网站需求、原计划的标签和组件名称；不提供网站的考核操作或任何判分。

要求引用需求原文并归类哪些动作需修改浏览器内的数据，哪些依赖外部服务，哪些只读。对可本地实现的动作，用同一份已验证的状态语言生成有可见前后值的更新；静态展示或成功提示不足以表示数据已变。若确实无可本地实现的更新，可明确说明并仍提交空方案。验收引用、字段和目标控件接线，最多一次公开格式修正。两种新页面仅相差更新处理器，二者均做保留对照。三站仍在全部预定官方操作上重放，病例另做确定性行为检查，均不替换主表。

新增生成上限 $0.35，功能复评上限 $2。完成并关闭调度的两项生成实际敞口合计低于 $0.33；连同两项原判官的最高 $15.80 和本补充 $2.35，仍在全轮 $20 内。各次未决预留照计。若新页与已判候选字节相同，复用同站同操作同判官的记录并写明来源。
