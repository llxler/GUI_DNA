# Web-Bench flex 匹配工作流复验

2026-11-18，按 canvas 的公开选项继续向后筛选，从 canvas 之后的项目按目录字母顺序选择。chart、color、expression-editor 缺少协议约定的 tasks.jsonl，demo 只有三条需求，dom 与 dom1 属同一文件管理器应用族，dom1、draw 已用于旧研究，esmodule 需要 Node.js 文件系统操作，expressjs 与 fastify 系列需要后端。flex 是下一个满足纯静态运行、init 加 20 条需求、新应用族的项目。其公开任务主要是响应式布局，末期包含拖拽交互，应单列项目。该选择在观察 flex 候选或成绩前作出。

沿用 matched_canvas 与 canvas_capacity 两个工作流的系统提示、全部 21 项公开需求、五个目标 4/8/12/16/20、同一 GPT-5 medium、双方 32,000-token 输出上限、一次公开修复及分别准备两次。flex 没有随项目分发的公共图片，双方均收到空资产列表。每行是一次准备及其五个目标，双方独立重复、同一费用上限。无库组准备自己的文字笔记，并逐目标独立写页面；另一组先生成完整库，再选配置。每阶段固定最终输出，全部生成后才评候选，评分只用同编号的原官方文件。

生成前分别用参考页和空白页校准五个文件，均须区别两者才发起付费请求。校准不通过则记录原始报告，停止本项目，不改测试或改挑项目。两批 canvas 账本全部关闭后才计算组限额：四美元、当天剩余的二十美元授权除以四、当时有效余额除以四，取三者最小值并向下取整到美分；若每组不足两美元不启动。未知费用预留按敞口计。截止时间继承首批。建库失败仍对应五个可判定的流程失败。因传输或预算缺失的位置保留 null，配对分析只用双方可观察的位置。两项目不合并分母，不用结果决定重复或追加重试。
