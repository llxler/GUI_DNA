# 端到端公开基准比较：下一阶段预备协议

状态：**设计草案，尚未生成新模型候选，尚未冻结为运行协议**。2026-11-17 的 `studies.end_to_end` 仅重算已有真实结果，不是新实验。新阶段须在付费前补齐项目、模型、种子、限额与时间；不修改任何旧阶段。

## 研究问题与比较方法

比较给定公开需求范围下两种完整流程：

1. AI 先实现一个可复用库、声明数据模式和确定性编译器；冻结首次通过预定公开检查的包，再由 GUI-DNA 为各目标生成方案。
2. 无库生成器从零编写页面，获得相同公开需求、运行合同、目标描述与允许反馈，不接收第 1 组的库、模式、编译器或文档示例。

基线知道需求及运行环境；“无库”不等于故意省略必要输入。比较结论是整体流程收益，不是单独输出格式的因果效应。同库自由代码历史实验保留在数据中，不纳入本次报告。

## 信息与资源匹配

- 在看新项目成绩前，按公开项目清单中的固定外部顺序选一个未用于调方法、无需外部密钥/账户的项目；记录排除理由，不按模型成绩筛选。
- 使用官方公开任务与官方测试，不自建新数据集。两组在准备阶段均见同一完整公开需求列表；每目标另标明累计前缀，不允许库单独获得额外未来需求。
- 两组享有相同**总**费用上限、同一推理强度/输出限制及公开反馈次数。GUI-DNA 的建库、失败和修复计入总额；基线可在自己的总额内自查/修复，但不能接收另一组产物。
- 先指定一个生成模型、一个建库模型和五个等间隔官方里程碑，运行两次独立重复（支持 seed 则记录，不支持则称重复请求）。正式规模由余额与已观测单调用上界约束，不以历史廉价模型费用估计所有模型。
- 每个重复单独建库；建库失败的预定目标仍纳入流程成功分母，另列失败原因。不得只报告成功建库后的条件概率。
- 复用成本按预定目标集合分摊：`pipeline = build + sum(plan + repair)`，`baseline = sum(code + repair)`；同时报总额、单目标额、成功率和每次重复，不从多个库挑最优。

## 评分与锁定

- 两组采用相同运行时与公开加载检查；隐藏行为判据不参与建库、方案或基线修复。若暴露官方子集，双方获得相同源码/反馈，并在独立协议中明确划分。
- 参考和空白校准在候选评分前完成。固定上游提交、任务源码、运行器、模型及供应商、请求、种子、超时、重试策略、单阶段账本及停止时间；全部输入和源码入哈希清单。
- 全部生成冻结后，分别评当前文件和同页 `init + task-1..k`；留存格式错误/截断、建库失败、传输缺失、全部测试报告。BOM 类型空过另做敏感性，不能改旧分数。
- 主统计单位为一次目标请求；同一项目内的里程碑/重复相关，不能把复制的基线或建库者数量当独立任务。先报告原始计数、通过率和逐重复差，不以小样本显著性包装结论。
