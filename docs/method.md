# GUI-DNA：数据、生成流程与评测口径

GUI-DNA 的当前研究对象是一条完整工作流：**AI 先写可复用行为库，再按需求选择方案**。对照是**不给这个库，从零编写页面**。目录入口和安装见根 [README](../README.md)；本文解释各自知道什么、输出什么，以及结果代表什么。

## 1. 公开需求与两条流程

Web-Bench 每项目提供初始化要求和 20 条逐步增加的需求。目标 task-k 要求实现从初始化到第 k 项的累计功能；不是只读一句话便猜测页面。

| 阶段 | AI 建库＋GUI-DNA | 无库从零生成 |
|---|---|---|
| 需求 | 建库者见全部公开需求；用库生成者见目标累计需求 | 见目标累计需求及运行合同 |
| 准备 | AI 输出源码、方案模式、编译器、文档示例 | 不接收另一组的任何库资产 |
| 冻结 | 首个通过格式/编译/加载检查的包固定，失败和费用保留 | 无库，不从生成后的另一组拷贝实现 |
| 每目标输出 | 数据方案，由冻结实现生成页面 | 完整页面源码 |
| 反馈 | 本阶段公开检查及编译器诊断，最多两次修复 | 本阶段公开格式/加载检查，最多两次修复 |
| 最终评分 | 全部生成完成后执行官方测试 | 同一评测环境与目标判据 |

“无库”不表示不知道需求。当前历史实验的建库阶段额外知道未来需求、花了额外计算，因此这是工作流比较，尚未匹配全部信息和总预算。下一阶段设计见 [end_to_end_protocol.md](end_to_end_protocol.md)。

模型提议的库不等于自建数据集：任务与评分来自公开 Web-Bench，模型只构建被评估方法使用的实现。旧自建二元组合/交错诊断保留历史，不进入当前论文。

## 2. 库与方案

一个包包含 `files`、`plan_schema`、确定性的 `compiler` 和 `examples`。建库模型自己提出实现与接口；主实验不提供人工函数槽位或页面外壳。一般模式检查负责约束格式，不能保证隐藏行为通过。

生成者选择方案 `p`，编译器计算 `compile(p, files)` 得到可运行页面。方案本身不生成任意函数体；库能表达什么，由冻结模式和实现共同决定。实际库可能暴露丰富行为，也可能仅有主题、字号等外观选项，必须区分。

旧 TodoMVC 人工库可用来直观说明组装：`toggle` 更新完成状态，`persistTodos` 保存新状态，`visibleByFilter` 推导筛选后的列表。把函数绑定到事件、后处理和视图就是一个方案。但这些人工准备的函数不是当前 AI 建库的证据；旧 dom1 库还使用了官方参考实现，来源必须明确。

## 3. 真实分母与两个端点

主表按建库者分列：两项目每列 80 个目标（2 项目 × 2 生成模型 × 20 任务），三项目每列 120 个目标，draw 每列 10 个目标。两个 GUI-DNA 条件使用各自的库，共用同一组真实无库基线；不能把基线复制后称为更多独立样本。列名明确指建库模型，目标生成模型另外分层报告。

- **当前文件**：保存的 task-k 页面通过官方 task-k 文件中所有断言。
- **完整历史**：同一保存页通过 `init + task-1..k` 全部文件，不能累加不同页面的成功。

| 研究 | 端点 | 无库基线 | GUI-DNA：GPT-5 建库 | GUI-DNA：Claude 建库 |
| --- | --- | --- | --- | --- |
| dom1、form | 当前 | 25/80（31.25%） | 43/80（53.75%） | 43/80（53.75%） |
| dom1、form | 完整历史 | 12/80（15.00%） | 20/80（25.00%） | 16/80（20.00%） |
| calculator、table、bom | 当前 | 42/120（35.00%） | 49/120（40.83%） | 44/120（36.67%） |
| calculator、table、bom | 完整历史 | 15/120（12.50%） | 8/120（6.67%） | 18/120（15.00%） |
| draw 五里程碑 | 当前 | 3/10（30.00%） | 8/10（80.00%） | 6/10（60.00%） |
| draw 五里程碑 | 完整历史 | 2/10（20.00%） | 2/10（20.00%） | 0/10（0.00%） |

BOM 六文件统一排除后，无库为 39/108，GPT-5 建库为 43/108，Claude 建库为 36/108；两套库相对基线分别为 +3.70 和 −2.78 个百分点。 原官方分数不改。历史 GPT-5 三项目小试没有无库条件，不补造比较。主视图中旧合并字段仅供对账，展示使用 `by_builder`、`by_project_builder` 和 `by_generator_builder`；敏感性、反馈和费用同样按建库者拆分。

## 4. 费用、失败与复现

费用分成一次建库与后续各目标生成/修复。公开说明复用次数，包含失败建库与未知传输预留，不能只展示短 JSON 的生成费。绘图单库建库回执分别为 GPT-5 约 $0.185241、Claude 约 $0.152952；对廉价生成模型，这笔固定成本可能高于从零生成本身。不能从一次强模型实验推断所有模型都省钱。

构建通过加载不代表库足够：某个有限计算器接口的 1,215 合法配置均无法通过初始化中的除零检查；反复选方案不能修复相同实现缺陷。有限搜索未找到正确页则只能标记未知，不能推断所有配置不可达。

当前 [主比较视图](../studies/results/end_to_end.json) 可用 `uv run python -m studies.end_to_end --check` 重算，含源哈希、真实记录路径、分组、完整历史和费用。它是新增报告视图，不覆盖原始 JSON。历史 `free_lib` 消融仍保存真实方法名、源码与分数，只退出当前论文和展示。完整旧结果见 [results.md](results.md)，公开产物边界见 [reproducibility.md](reproducibility.md)。
